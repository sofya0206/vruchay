# Наблюдение за сервисом: пошаговая инструкция

**Сколько займёт:** 10 минут.
**Зачем:** узнавать о падении сервиса от робота, а не от клиента.

> ## Резервные копии не делались ни одной ночи — найдено и починено 05.08.2026
>
> В crontab стояло `. /etc/vruchay-backup.env && backup.sh`. Точка присваивает
> переменные оболочке, но **не экспортирует** их, а скрипт запускается отдельным
> процессом и не видит ничего. Каждую ночь копия падала на «не задана база».
> Сообщение уходило в `/var/log/vruchay-backup.log` — файл, который никто
> не открывал.
>
> Учебное восстановление в своё время прошло успешно и ошибку не поймало:
> оно запускалось руками, с переменными уже в окружении. **Проверка, которая
> идёт не тем же путём, что боевой запуск, не доказывает ничего.**
>
> Теперь `backup.sh` читает `/etc/vruchay-backup.env` сам, через `set -a`,
> и от строки в crontab больше не зависит. Первая настоящая копия легла
> в хранилище 05.08.2026 в 09:00 UTC.
>
> **Осталось:** оповещение о неудачной копии. Без него следующая тихая
> поломка проживёт ровно столько же — до случайной проверки.

## Что уже сделано и работает само

Не всё нужно настраивать — часть уже стоит на сервере:

- **Контейнеры перезапускаются сами.** Если приложение упадёт, Docker
  поднимет его снова. Проверено: перезапуск Docker поднял все пять служб
  без вмешательства.
- **Проверка живости приложения.** Docker раз в 30 секунд опрашивает
  `/health`; неотвечающий контейнер считается больным и перезапускается.
- **Журналы ограничены.** Пять файлов по 20 МБ на контейнер, дальше
  старые затираются. Без этого журналы растут, пока не кончится диск.
- **Еженедельная уборка образов.** За первый день работы старые слои
  сборок заняли 16 ГБ из 30 — диск дошёл до 92%, и следующая сборка
  упала бы от нехватки места. Теперь чистится само.
- **Ежедневная копия базы** в 03:00, зашифрованная, в отдельный бакет.

Чего всё это **не** ловит: сервер выключился, кончилось место, отвалилась
сеть, истёк сертификат. Об этом должен сообщить кто-то снаружи.

## Шаг 1. Завести наблюдение

1. Откройте [uptimerobot.com](https://uptimerobot.com), зарегистрируйтесь
   (бесплатного тарифа хватает: 50 проверок, интервал 5 минут)
2. **Add New Monitor**, заполните:

| Поле | Значение |
|---|---|
| Monitor Type | HTTP(s) |
| Friendly Name | Вручай |
| URL | `https://vruchay.ru/health` |
| Monitoring Interval | 5 minutes |

3. **Advanced** → включите **SSL certificate expiry** — предупредит
   за 7 дней до истечения сертификата

> Почему именно `/health`, а не главная страница: главная отдаётся
> Caddy из готовых файлов и будет открываться даже когда приложение
> и база лежат. `/health` проходит через приложение — если он ответил,
> значит живо всё, включая подключение к базе.

## Шаг 2. Настроить оповещения

**Alert Contacts** → добавьте:

- **Почту** — придёт письмо при падении и при восстановлении
- **Telegram** (рекомендую) — быстрее почты:
  1. Найдите в Telegram бота `@UptimeRobotBot`, нажмите Start
  2. В UptimeRobot: Alert Contacts → Add → Telegram
  3. Скопируйте выданный код боту

Отметьте новый контакт в настройках проверки, иначе оповещения
никуда не пойдут.

---

## Шаг 3. Проверить, что работает

Не верьте настройке на слово — сломайте её нарочно:

1. Временно поменяйте в проверке адрес на `https://vruchay.ru/нет-такой-страницы`
2. Через 5–10 минут должно прийти оповещение
3. Верните адрес обратно, дождитесь оповещения о восстановлении

Ненастроенное оповещение и настроенное выглядят одинаково ровно
до того дня, когда оно понадобится.

## Что смотреть, когда пришло оповещение

```bash
ssh -i ~/.ssh/vruchay vruchay@178.72.160.214
```

| Команда | Что покажет |
|---|---|
| `cd /opt/vruchay && docker compose -f docker-compose.prod.yml ps` | какие службы живы |
| `docker compose -f docker-compose.prod.yml logs --tail 50 api` | последние ошибки приложения |
| `docker compose -f docker-compose.prod.yml logs --tail 50 worker` | ошибки печати документов |
| `df -h /` | не кончилось ли место |
| `free -h` | не кончилась ли память |

**Самая частая причина** на нашей конфигурации — нехватка места или
памяти при сборке. Освободить место:

```bash
ssh -i ~/.ssh/vruchay vruchay@178.72.160.214 'docker image prune -f && df -h /'
```

Поднять всё заново, если что-то не встало:

```bash
ssh -i ~/.ssh/vruchay vruchay@178.72.160.214 'cd /opt/vruchay && docker compose -f docker-compose.prod.yml up -d'
```
