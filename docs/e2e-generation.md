# Сквозная проверка генерации PDF

Автотестом это не покрыто намеренно: проверка требует поднятого приложения,
Redis, S3 и настоящего браузера — в обычном прогоне тестов такого окружения нет.
Прогоняется вручную перед каждым релизом и после любых правок рендера, шрифтов
или вёрстки листа.

## Подготовка

```bash
docker compose -f docker-compose.dev.yml up -d
pnpm --filter @gramota/server build && node apps/server/dist/main.js
pnpm --filter @gramota/web dev
```

В `apps/server/.env` для локального запуска нужны:

```
PUBLIC_URL=http://localhost:5173
PLAYWRIGHT_CHANNEL=chrome
```

`PLAYWRIGHT_CHANNEL=chrome` использует установленный в системе Google Chrome.
В продовом образе переменная пустая — там берётся Chromium, поставляемый
с Playwright (`playwright install --with-deps chromium` на этапе сборки).

## Что проверяем

1. Создать документ, положить на лист текстовые блоки с переменными
   (`%name`, плюс любая колонка таблицы).
2. Импортировать список участников — обязательно с кириллицей, буквой «ё»
   и двойной фамилией через дефис.
3. Запустить генерацию, дождаться статуса `done` без ошибок.
4. Скачать архив и **извлечь текст из PDF**:

```bash
pdftotext -enc UTF-8 "Иванов Иван Иванович.pdf" -
```

**Признак успеха** — текст извлекается и читается:

```
Награждается Иванов Иван Иванович
занявший 1 место
```

**Признаки провала**, ради которых проверка и существует:

- вместо букв квадраты или пусто — шрифт не встроился в PDF;
- текст не извлекается вообще — лист отрисовался картинкой, а не текстом;
- переменные остались как `%name` — данные строки не доехали до страницы рендера;
- фон отсутствует — страница напечаталась раньше загрузки изображения.

## Очередь: отмена, перезапуск, порядок

Эти четыре проверки автотестами закрыты только со стороны кода
(`src/generation/quota.test.ts`, `queue-order.test.ts`): подмена Prisma
доказывает правила, но не доказывает, что Redis, BullMQ и база ведут себя
так, как мы о них думаем. Прогоняются после правок очереди.

1. **Отмена на середине.** Пакет на 200 строк, нажать «Отменить» примерно
   на тридцатой. Признак успеха: печать прекращается за секунды, состояние
   `canceled`, созданные файлы на месте и скачиваются.
   На главной странице кабинета остаток пробы уменьшился ровно на созданные,
   а не на все 200 — это и есть возврат квоты.

2. **Перезапуск воркера.** Пакет на 200 строк, на середине:

```bash
docker compose -f docker-compose.prod.yml restart worker   # или Ctrl+C локально
```

   Признак успеха: через минуту (протухает блокировка BullMQ) воркер берёт
   незаконченные части снова и в журнале пишет «часть N задания …». Число
   файлов в конце — ровно 200, не больше: повторных списаний нет.
   **Признак провала**, ради которого проверка и существует: в архиве
   оказалось больше файлов, чем строк.

3. **Порядок в очереди — главная проверка этой части.** Поставить пакет
   на 300 строк, **дождаться, пока он реально начнёт печататься**, и только
   потом поставить пакет на 5 строк по другому документу.
   Признак успеха: маленький заканчивается в пределах минуты, не дожидаясь
   большого. Ставить оба до старта воркера бессмысленно — так проверяются
   приоритеты, а не то, ради чего пакет режется на части.

4. **Продолжение прерванного.** Убить воркера посреди пакета на 200 строк
   и дождаться, пока задание перейдёт в «Выпуск прервался». Нажать
   **«Продолжить»**.
   Признак успеха: печатаются только недостающие строки, а остаток
   бесплатной пробы в кабинете уменьшается ровно на них.
   **Признак провала**: остаток уменьшился на все 200 — значит продолжение
   пошло как новый выпуск и человек заплатил дважды.

5. **Лимит на организацию.** Поставить четыре пакета по разным документам
   подряд: четвёртый должен получить отказ с внятным текстом, а не встать
   в очередь.

## Выдача: архив и общий PDF

6. Скачать архивом с шаблоном имени `%number %name` — файлы пронумерованы.
   Проверить кириллицу и тёзок: у второго Иванова в имени появляется `(2)`.
   Отдельно — распаковать архив **в Windows**: имена вроде `CON` и суррогатные
   пары ломаются именно там, и юникс-распаковщик этого не покажет.
7. Скачать «одним PDF на печать» — число страниц равно числу документов
   (для одностраничного макета), файл открывается и печатается целиком.
8. Пакет крупнее `PRINT_MERGE_LIMIT_FILES` (по умолчанию 300): кнопка
   «Одним PDF на печать» должна быть **погашена и объяснять причину**
   прямо в окне скачивания. Голый JSON с отказом в новой вкладке —
   признак провала: значит предел проверяется только на сервере.

именно встроены, а не подставлены системные.

## Известные грабли

- **414 от Fastify**: подписанный токен длиннее 100 символов, а это лимит
  параметра пути по умолчанию. Лечится `maxParamLength` — уже выставлен в `main.ts`.
- **Порт 3000 занят прошлым процессом**: сервер молча падает с `EADDRINUSE`,
  а задание обрабатывает старая версия кода. Перед перезапуском:
  `lsof -ti:3000 | xargs kill -9`.
- **Пустая переменная в готовом файле** — обычно не ошибка подстановки,
  а переименованная или отсутствующая колонка в таблице получателей.
