# GET /api/audit

Журнал действий организации, новые сверху, страницами. В журнал попадает только то, у чего есть последствия снаружи: выпуск и рассылка, отзыв проверки, окончательное удаление, изменения в составе сотрудников, выдача и отзыв токенов. Открытие страниц и правка макета не записываются.

Смотреть могут владелец и управляющий (в том числе по токену с ролью `admin`). Подробности события (`meta`), адрес (`ip`) и идентификатор сотрудника в ответ не входят — только имя и почта, скопированные в момент действия, чтобы запись оставалась читаемой после удаления сотрудника. Действия системы (например, ночная очистка) идут с пустыми `actorName` и `actorEmail`.

Известные значения `action` (собраны по коду сервера):

| action | Что произошло |
|---|---|
| document.trash | Материал отправлен в корзину |
| document.purge | Материал удалён навсегда вместе с выданными файлами |
| generation.start | Запущен выпуск |
| generation.cancel | Выпуск отменён |
| generation.resume | Выпуск возобновлён |
| validation.fix | Исправлены строки по результатам проверки («Исправлено строк: N») |
| validation.exclude | Снята отметка со строк по результатам проверки («Снята отметка со строк: N») |
| mail.send | Разосланы письма участникам с документами («Разослано писем участникам: N») |
| mailing.send | Запущена рассылка по списку («Рассылка (<вид>): писем N») |
| mailing.resend | Повторная отправка недоставленных писем |
| registry.reissue | Перевыпуск документов из реестра («Перевыпущено документов: N») |
| registry.resend | Повторная отправка писем из реестра («Переотправлено писем из реестра: N») |
| team.invite | Приглашён сотрудник |
| team.role | Изменена роль сотрудника |
| team.remove | Сотрудник удалён из организации |
| token.create | Выдан токен API |
| token.revoke | Отозван токен API |
| platform.plan | Владелец сервиса сменил тариф организации |
| platform.verified | Владелец сервиса выдал или снял значок верифицированного эмитента |

## Запрос

Параметры строки запроса:

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| limit | number | нет | Сколько записей на странице: целое от 1 до 200. По умолчанию 50. |
| offset | number | нет | Сколько записей пропустить: целое, не меньше 0. По умолчанию 0. |
| action | string | нет | Показать только события с этим `action` (точное совпадение), до 60 знаков. |

## Ответ

`200 OK`

| Поле | Тип | Описание |
|---|---|---|
| total | number | Всего записей, подходящих под фильтр. |
| limit | number | Применённый размер страницы. |
| offset | number | Применённое смещение. |
| items | array | Записи, новые сверху. |
| items[].id | string | Идентификатор записи (числовой, отдаётся строкой). |
| items[].action | string | Код действия, см. таблицу выше. |
| items[].summary | string | Человекочитаемое описание. |
| items[].actorName | string | Имя сотрудника на момент действия; по токену — `Токен «<название>»`; пустая строка — система. |
| items[].actorEmail | string | Почта сотрудника на момент действия; по токену и у системы — пустая строка. |
| items[].targetType | string \| null | Тип предмета действия (`token`, `document` и т. п.). |
| items[].targetId | string \| null | Идентификатор предмета действия. |
| items[].createdAt | string (ISO 8601) | Когда. |

## Ошибки

| Код | Когда |
|---|---|
| 400 | `limit` не целое от 1 до 200, `offset` отрицательный или не целое, `action` длиннее 60 знаков — стандартное сообщение Zod. |
| 401 | Нет действующего токена и нет cookie-сессии. `{"statusCode":401,"message":"Требуется вход в систему","error":"Unauthorized"}` |
| 403 | Роль `member` (в том числе токен с ролью `member`): «Недостаточно прав для этого действия». |

## Пример

```bash
curl "https://vruchay.ru/api/audit?limit=50&offset=0&action=generation.start" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN"
```
