# POST /api/mailing/audience

Показывает до отправки, кому письмо уйдёт и кому не уйдёт, — тем же расчётом, что и `POST /api/mailing/send`. Ничего не отправляет и ничего не пишет в базу. Считается по **сохранённому** шаблону, а не по набранному в форме тексту: пока письмо не сохранено через `POST /api/mailing/templates/{documentId}`, в ответе приходит `refusal` и пустой список.

Материал здесь один — в отличие от отправки, где их может быть до двадцати. Причины пропуска: нет адреса, некорректный адрес, адрес уже встречался в этой же рассылке, по этому материалу в этом потоке письмо на адрес уже уходило, нет согласия на рекламную рассылку (только для `marketing`), документ по строке ещё не выпущен (когда шаблон обещает вложение).

`refusal` — не ошибка запроса, а причина, по которой отправка не состоится: нет шаблона, отправитель удалён, домен отправителя перестал быть подтверждённым, почта вообще не настроена, у рекламного письма стёрли рекламодателя. Лимиты общего домена здесь **не** проверяются — они срабатывают только при самой отправке.

## Запрос

Тела запроса — строгая схема, лишние поля запрещены.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| documentId | string (UUID) | да | Материал организации (не удалённый) |
| kind | `transactional` \| `marketing` | да | Поток письма; шаблон ищется по нему же |
| source | `table` \| `manual` | да | Получатели из таблицы материала (только отмеченные строки) или из списка адресов |
| emails | string | нет | Список адресов одной строкой, до 60 000 символов; разделители — перевод строки, запятая, точка с запятой, пробел. Учитывается только при `source: "manual"` |

При `source: "manual"` адрес, найденный в таблице материала, получает её данные и выпущенный по строке файл; не найденный уходит без имени и без вложения.

```json
{
  "documentId": "9e8d7c6b-5a4f-4e3d-2c1b-0a9f8e7d6c5b",
  "kind": "transactional",
  "source": "table"
}
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| documentId | string (UUID) | Материал |
| title | string | Название материала |
| refusal | string \| null | Почему отправка невозможна; `null` — препятствий нет |
| willSend | number | Сколько писем уйдёт |
| letters | array | Первые 50 получателей: `{email, name}`; список намеренно обрезан |
| skipped | array | Все пропущенные: `{name, email, reason}` |

```json
{
  "documentId": "9e8d7c6b-5a4f-4e3d-2c1b-0a9f8e7d6c5b",
  "title": "Грамоты участникам",
  "refusal": null,
  "willSend": 2,
  "letters": [
    { "email": "ivanova@example.com", "name": "Иванова Мария Сергеевна" },
    { "email": "petrov@example.com", "name": "Петров Олег Иванович" }
  ],
  "skipped": [
    { "name": "Кузнецов Олег", "email": "", "reason": "нет адреса" },
    { "name": "Сидорова Анна", "email": "anna@", "reason": "некорректный адрес «anna@»" }
  ]
}
```

Возможные значения `reason`: «нет адреса», «некорректный адрес «…»», «адрес уже есть в этой рассылке», «по этому материалу письмо на этот адрес уже уходило», «нет согласия на рекламную рассылку», «документ ещё не создан».

Возможные значения `refusal`: «Сначала сохраните письмо: считаем по сохранённому тексту, а не по набранному» (или «Рекламное письмо для этого материала не сохранено — нажмите «Сохранить письмо»» при `kind: "marketing"`), «Отправитель не найден», «Домен example.ru не подтверждён — отправка невозможна», «Отправка писем не настроена — обратитесь в поддержку», «Укажите рекламодателя: по закону получатель должен видеть, чья это реклама».

## Ошибки

| Код | Когда |
|---|---|
| 400 | `documentId` не UUID: «Invalid UUID» |
| 400 | `kind` или `source` не из списка: «Invalid option: expected one of "transactional"\|"marketing"», «Invalid option: expected one of "table"\|"manual"» |
| 400 | Лишнее поле в теле: «Unrecognized key: "…"» |
| 400 | `emails` длиннее 60 000 символов: «Too big: expected string to have <=60000 characters» |
| 401 | Нет токена или сессии |
| 404 | Материала нет, он удалён или чужой: «Материал не найден» |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/mailing/audience" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"documentId":"'"$DOCUMENT_ID"'","kind":"transactional","source":"table"}'
```
