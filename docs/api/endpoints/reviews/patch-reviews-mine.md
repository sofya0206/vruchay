# PATCH /api/reviews/mine

Оставить отзыв о сервисе или переписать уже оставленный. Один вызов на оба случая:
если отзыв у организации есть, он заменяется, если нет — заводится.

Отзыв всегда уходит на проверку человеком: сразу после этого запроса `status`
становится `pending`, `moderatorNote` и `publishedAt` очищаются. Правка снимает
публикацию — на витрине не должно оказаться непроверенного текста только потому,
что прежний вариант когда-то одобрили. Обратная сторона удобна: исправленный
после замечания отзыв не остаётся отклонённым навсегда.

Опубликовать отзыв через API нельзя: решение принимает оператор сервиса.

## Запрос

Тело — JSON.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| authorName | string 2…120 | да | Как подписать отзыв. Из профиля не берётся — автор пишет сам. |
| authorRole | string 2…120 | да | Должность автора. |
| orgName | string 2…200 | да | Название организации так, как её назвать на витрине. |
| text | string 40…2000 | да | Текст отзыва. Нижняя граница не придирка: по «всё ок» невозможно понять, чем сервис пригодился. |
| rating | integer 1…5 | нет | Оценка. Без неё в отзыве останется `null`. |

Пробелы по краям всех строк обрезаются до проверки длины.

```json
{
  "authorName": "Мария Петрова",
  "authorRole": "Ответственный секретарь",
  "orgName": "Учебный центр «Развитие»",
  "text": "Раньше на двести грамот уходило два дня: сверить фамилии, разложить по шаблону, разослать. Теперь загружаем таблицу и через полчаса рассылка уже ушла.",
  "rating": 5
}
```

## Ответ

`200 OK` — сохранённая запись отзыва целиком.

| Поле | Тип | Описание |
|---|---|---|
| id | string (UUID) | Идентификатор отзыва. |
| orgId | string (UUID) | Организация автора. |
| userId | string (UUID) | Сотрудник, впервые оставивший отзыв. При правке не меняется. |
| authorName | string | Как подписан автор. |
| authorRole | string | Должность автора. |
| orgName | string | Организация. |
| text | string | Текст отзыва. |
| rating | number \| null | Оценка. |
| status | string | Всегда `pending` сразу после этого запроса. |
| moderatorNote | string \| null | Всегда `null` сразу после этого запроса. |
| createdAt | string (ISO 8601) | Когда отзыв заведён. При правке не меняется. |
| publishedAt | string (ISO 8601) \| null | Всегда `null` сразу после этого запроса. |

Ответ шире, чем у `GET /api/reviews/mine`: здесь отдаётся вся запись, включая
`orgId` и `userId`.

```json
{
  "id": "c3d4e5f6-a7b8-4c9d-8e0f-1a2b3c4d5e6f",
  "orgId": "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d",
  "userId": "f0e1d2c3-b4a5-4968-9788-6a5b4c3d2e1f",
  "authorName": "Мария Петрова",
  "authorRole": "Ответственный секретарь",
  "orgName": "Учебный центр «Развитие»",
  "text": "Раньше на двести грамот уходило два дня: сверить фамилии, разложить по шаблону, разослать. Теперь загружаем таблицу и через полчаса рассылка уже ушла.",
  "rating": 5,
  "status": "pending",
  "moderatorNote": null,
  "createdAt": "2026-05-18T12:40:11.000Z",
  "publishedAt": null
}
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | `authorName` короче 2 знаков или отсутствует — «Укажите, как вас зовут»; `authorRole` — «Укажите вашу должность»; `orgName` — «Укажите организацию»; `text` короче 40 знаков — «Напишите хотя бы пару предложений». Превышение верхних границ и `rating` вне 1…5 — стандартное сообщение Zod. |
| 401 | Нет действующего токена и нет cookie-сессии. |
| 413 | Тело больше 1 МБ. |

## Пример

```bash
curl -X PATCH "https://vruchay.ru/api/reviews/mine" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "authorName": "Мария Петрова",
    "authorRole": "Ответственный секретарь",
    "orgName": "Учебный центр «Развитие»",
    "text": "Раньше на двести грамот уходило два дня. Теперь загружаем таблицу и через полчаса рассылка уже ушла.",
    "rating": 5
  }'
```
