# GET /api/award-rules/{id}

Набор правил со всеми правилами, условиями и выходами — то, что показывает конструктор и применяет движок раскладки. Правила отдаются по возрастанию `position`: порядок в этом массиве и есть приоритет, выигрывает первое совпавшее правило.

Набор другой организации и удалённый набор отдаются как ненайденные (404), а не как запрещённые: 403 подтвердил бы, что такой идентификатор существует.

Записи, сохранённые прошлой версией формата, проверяются схемой на выходе, а не на раскладке: если `conditions` или `outputs` в базе не соответствуют текущему контракту, ответ будет ошибкой сервера, а не молча посчитанной раскладкой.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `id` | UUID (путь) | да | Идентификатор набора правил |

Тела нет.

## Ответ

`200 OK` — набор правил в общем контракте `AwardRuleSet`.

Поля `id`, `name`, `schemaVersion`, `groupColumn`, `statusColumn`, `rules[]` (с `position`, `enabled`, `label`, `match`, `conditions`, `action`, `outputs`) разобраны в [reference/award-rules.md](../../reference/award-rules.md) — там же полный пример ответа и таблицы условий и выходов.

Признака `isDefault` в этом ответе нет: он живёт только в списке `GET /api/award-rules`.

## Ошибки

| Код | Когда |
|---|---|
| 400 | `Некорректный идентификатор` — `id` не UUID |
| 401 | Нет токена или сессии |
| 404 | `Набор правил не найден` — нет такого, он удалён или принадлежит другой организации |

## Пример

```bash
curl "https://vruchay.ru/api/award-rules/$RULE_SET_ID" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN"
```
