# POST /api/documents/{id}/awards/rule-set

Выбирает, по какому набору правил награждается это мероприятие. Сам набор принадлежит организации и живёт отдельно (`/api/award-rules`); здесь запоминается только ссылка на него у документа. Привязка ничего не считает и не выпускает — она нужна, чтобы `POST /api/documents/{id}/awards/preview` знал, какие правила брать, когда тело запроса пустое.

Привязка одна: повторный вызов заменяет прежний набор. `ruleSetId: null` отвязывает набор от документа.

И документ, и набор проверяются на принадлежность организации; чужие отдаются как ненайденные.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `id` | UUID (путь) | да | Идентификатор документа-мероприятия |

Тело:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `ruleSetId` | UUID \| null | да | Набор правил; `null` — отвязать. Поле обязано присутствовать |

```json
{ "ruleSetId": "7c1f7d1e-2b5e-4c3a-9c1a-8d2f0a6b1e11" }
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| `ok` | boolean | всегда `true` |
| `ruleSetId` | UUID \| null | что теперь привязано |

```json
{ "ok": true, "ruleSetId": "7c1f7d1e-2b5e-4c3a-9c1a-8d2f0a6b1e11" }
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | `Некорректный идентификатор` — `id` в пути не UUID |
| 400 | `ruleSetId` отсутствует или не UUID и не `null` (сообщение Zod) |
| 401 | Нет токена или сессии |
| 404 | `Документ не найден` |
| 404 | `Набор правил не найден` — набора нет, он удалён или принадлежит другой организации |
| 413 | Тело больше 1 МБ |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/documents/$DOCUMENT_ID/awards/rule-set" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"ruleSetId":"7c1f7d1e-2b5e-4c3a-9c1a-8d2f0a6b1e11"}'
```
