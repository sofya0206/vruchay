# DELETE /api/tokens/{id}

Отзывает токен: с этого момента запросы с ним получают 401. Запись о токене не удаляется, а помечается временем отзыва (`revokedAt`) — чтобы позже можно было ответить, кто и когда завёл этот доступ. Из списка `GET /api/tokens` отозванный токен пропадает; повторный отзыв того же токена отвечает 404. Отзыв записывается в журнал действий событием `token.revoke`.

**По токену API недоступно, только из кабинета (cookie-сессия).**

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| id | string (UUID) | да | Идентификатор токена из `GET /api/tokens` или ответа на выдачу. |

Тела нет.

## Ответ

`200 OK`

| Поле | Тип | Описание |
|---|---|---|
| ok | boolean | Всегда `true`. |
| name | string | Название отозванного токена. |

```json
{
  "ok": true,
  "name": "выгрузка из CRM"
}
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | `id` не UUID: «Некорректный идентификатор». |
| 401 | Нет cookie-сессии. `{"statusCode":401,"message":"Требуется вход в систему","error":"Unauthorized"}` |
| 403 | Запрос пришёл по токену API: «Это действие доступно только человеку, вошедшему в кабинет. Токен API управлять сотрудниками не может.» |
| 403 | Роль `member`: «Недостаточно прав для этого действия». |
| 404 | Токена с таким `id` в вашей организации нет, либо он уже отозван: «Токен не найден». Чужой токен тоже даёт 404. |

## Пример

```bash
curl -X DELETE "https://vruchay.ru/api/tokens/$TOKEN_ID" \
  -b cookies.txt
```
