# POST /api/registry/revoke

Отозвать проверку у пачки документов или вернуть её. Сами файлы остаются —
их могли скачать и распечатать; меняется ответ страницы проверки: отозванный
документ показывает красную страницу с публичной причиной. Действие
синхронное: после ответа состояние уже изменено. В журнал организации
пишется запись `verify.revoke` или `verify.restore` (внутренняя причина
в журнал не попадает).

Цель задаётся одним из двух способов: список `fileIds` (отмеченные
документы) или `filter` — всё, что находится по отбору реестра. Отбор
обязан быть сужен хотя бы материалом, мероприятием или периодом: пустой
отбор означал бы «всё выданное организацией за всё время».

Отзыв подтверждается числом: в `expectedCount` клиент присылает, сколько
документов он показал человеку, и сервер отказывает, если по цели сейчас
находится другое число. Перед вызовом получите это число через
`POST /api/registry/revoke/preview`.

Возврат проверки (`revoked: false`) возможен только по `fileIds`. Он снимает
лишь отметку: `revokedAt` и причины остаются историей документа.

## Запрос

Тело — JSON.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `fileIds` | UUID[] 1…500 | либо оно, либо `filter` | Отмеченные документы. |
| `filter` | object | либо оно, либо `fileIds` | Отбор реестра ([reference/registry-filter.md](../../reference/registry-filter.md)); должен содержать хотя бы одно из `documentId`, `event`, `from`, `to`. |
| `revoked` | boolean | да | `true` — отозвать, `false` — вернуть проверку. |
| `expectedCount` | integer 1…1 000 000 | да | Сколько документов подтверждено; должно совпасть с тем, что найдётся сейчас. |
| `reasonPublic` | string ≤ 300 | нет | Причина, которую увидит человек на странице проверки. Пишется только при `revoked: true` и только если поле передано; пустая строка стирает прежнюю. |
| `reasonInternal` | string ≤ 1000 | нет | Причина для владельца и управляющего. Правила те же. |

Повторный отзыв уже отозванного документа без причин прежние причины не
стирает.

```json
{
  "filter": { "documentId": "b1c2d3e4-f5a6-4b7c-8d9e-0f1a2b3c4d5e" },
  "revoked": true,
  "expectedCount": 640,
  "reasonPublic": "Протокол соревнований пересмотрен",
  "reasonInternal": "Ошибка судейской бригады, письмо от 20.06"
}
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| `changed` | number | Сколько документов изменено. |
| `names` | string[] | Имена получателей изменённых документов (пустые пропущены), новые выпуски первыми. |

```json
{ "changed": 640, "names": ["Иванова Мария Петровна", "Петров Олег Игоревич"] }
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | Переданы и `fileIds`, и `filter`, или ни одно — «Укажите либо документы, либо отбор». |
| 400 | Отбор без `documentId`/`event`/`from`/`to` — «Отбор для массового отзыва должен быть сужен материалом, мероприятием или периодом». |
| 400 | `revoked: false` с `filter` — «Возврат проверки — только по отмеченным документам». |
| 400 | Нет `revoked` — «Не указано, отзывать проверку или возвращать». |
| 400 | `expectedCount` < 1 или отсутствует — «Подтвердите число документов»; > 1 000 000 — стандартное сообщение Zod. |
| 400 | Пустой `fileIds` — «Не отмечено ни одного документа»; больше 500 — «За раз можно обработать не больше 500 документов»; элемент не UUID — «Некорректный идентификатор документа». |
| 400 | Длинные причины — «Публичная причина — не длиннее 300 знаков», «Внутренняя причина — не длиннее 1000 знаков». |
| 400 | Ошибки внутри `filter`: «Некорректный идентификатор материала», «Неизвестное состояние документа», «Неизвестное состояние письма», «Не удалось разобрать дату начала периода», «Не удалось разобрать дату конца периода». |
| 400 | По цели ничего не нашлось (в том числе все `fileIds` чужие или удалены) — «Ни один из документов не найден». |
| 400 | Число не сошлось — «Список изменился: сейчас по этому отбору N документов, а подтверждено M. Обновите список и подтвердите снова.» |
| 401 | Нет токена или сессии. |
| 403 | Роль `member` — «Недостаточно прав для этого действия». |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/registry/revoke" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"fileIds":["'"$FILE_ID"'"],"revoked":true,"expectedCount":1,"reasonPublic":"Выдан по ошибке"}'
```
