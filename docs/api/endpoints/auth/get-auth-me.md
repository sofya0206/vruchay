# GET /api/auth/me

Возвращает, от чьего имени выполняются запросы: имя, роль в организации и признак, что это организация самого сервиса. Удобен как первая проверка токена — по нему видно, что заголовок `Authorization` принят и какая роль у токена.

При входе по токену API «пользователь» — это сам токен: `email` пустой, `name` имеет вид `Токен «<название токена>»`, `role` — роль, заданная при выдаче токена (`member` или `admin`). При входе из кабинета (cookie-сессия) возвращаются имя и почта сотрудника и его роль в организации.

## Запрос

Параметров нет.

## Ответ

`200 OK`

| Поле | Тип | Описание |
|---|---|---|
| email | string | Почта сотрудника. По токену — пустая строка. |
| name | string | Имя сотрудника. По токену — `Токен «<название>»`. |
| role | string | Роль: `owner`, `admin` или `member`. У токена — только `member` или `admin`. |
| isPlatform | boolean | `true` только у организации, которой принадлежит сам сервис (`PLATFORM_ORG_ID`). Для клиентов всегда `false`. |

```json
{
  "email": "",
  "name": "Токен «выгрузка из CRM»",
  "role": "member",
  "isPlatform": false
}
```

## Ошибки

| Код | Когда |
|---|---|
| 401 | Нет заголовка `Authorization` с действующим токеном и нет cookie-сессии; токен отозван. `{"statusCode":401,"message":"Требуется вход в систему","error":"Unauthorized"}` |

## Пример

```bash
curl "https://vruchay.ru/api/auth/me" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN"
```
