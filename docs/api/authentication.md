# Аутентификация

## Токен

API опознаёт вызывающего по заголовку:

```
Authorization: Bearer vru_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
```

Токен выдаётся в кабинете, в разделе доступа по API, и состоит из приставки `vru_`
и 32 случайных байт в base64url. Приставка не украшение: по ней сервисы поиска утечек
(GitHub, GitLab) узнают секрет в чужом репозитории и предупреждают владельца.

Полный токен показывается **один раз**, в ответе на его создание. На сервере лежит только
хеш SHA-256, восстановить строку нельзя. Потеряли — отзовите и выдайте новый.

## Что даёт токен

Токен принадлежит организации, а не человеку. Он видит те же документы, получателей,
задания и реестр, что и сотрудник этой организации с той же ролью. Идентификатор
организации всегда берётся из токена и никогда из тела или адреса запроса: подставить
чужой `orgId` невозможно, а обращение к чужому объекту отвечает `404`, а не `403`, —
чтобы не подтверждать, что объект существует.

## Роли

У токена своя роль, выбранная при выдаче: `member` или `admin`. У человека роль может быть
ещё и `owner`. Часть действий закрыта ролью:

| Роль | Что доступно |
| --- | --- |
| `member` | Документы, получатели, проверка, выпуск, чтение реестра, рассылка |
| `admin` | То же плюс удаление документов, отзыв выданного, домены и отправители, интеграции |
| `owner` | То же плюс безвозвратное удаление документа |

Роль `owner` токену выдать нельзя. Если действие требует роли выше вашей, ответ — `403`
с сообщением «Недостаточно прав для этого действия».

## Чего токен не может

Всё, что управляет людьми, закрыто для токенов наглухо и не открывается ролью:

- приглашение и удаление сотрудников, смена их ролей — `/api/team/*`;
- смена пароля;
- выдача и отзыв токенов — `/api/tokens/*`.

Причина простая: токен, умеющий выдавать себе новые токены, — это доступ, который нельзя
отозвать, потому что он тут же выдаст себе следующий. А утёкший токен, умеющий менять роли,
означал бы потерю организации целиком.

Такие запросы отвечают `403` с сообщением: «Это действие доступно только человеку, вошедшему
в кабинет. Токен API управлять сотрудниками не может.»

Отдельно закрыт раздел самого сервиса — счета, заявки, модерация отзывов. Туда токен
не пускают ни при каких правах.

## Сессия человека

Кабинет работает не на токенах, а на httpOnly-cookie `gramota_session` со сроком жизни
семь суток. Оба способа разбирает один и тот же слой: сперва проверяется заголовок
`Authorization`, и только если токена нет — cookie. Для интеграции нужен именно токен:
вход по паролю программе недоступен, а формы входа защищены ограничением частоты.

## Гигиена

- Держите токен в переменной окружения, а не в коде и не в репозитории.
- На организацию действует не больше **десяти** одновременно действующих токенов.
  Одиннадцатый не выдастся, пока не отзовёте лишние.
- Отозванный токен перестаёт работать сразу, но запись о нём остаётся: нужно уметь
  ответить, кто и когда завёл этот доступ.
- У каждого токена видно время последнего использования — так находят забытые.
  Отметка обновляется не чаще раза в час, поэтому «только что» она не показывает.

## Ошибки

| Код | Когда |
| --- | --- |
| `401` | Заголовка нет, токен неизвестен или отозван |
| `403` | Роли не хватает, либо действие доступно только человеку |
| `404` | Объект принадлежит другой организации либо не существует |
