# Задание на выпуск

Форма записи о выпуске, которую возвращают `POST /api/documents/{id}/generate`,
`POST /api/jobs/{jobId}/resume`, `POST /api/jobs/{jobId}/cancel`,
`GET /api/jobs/{jobId}` и `GET /api/documents/{id}/jobs` (массивом). Это запись
таблицы `generation_jobs` целиком, без отбора полей
(`apps/server/prisma/schema.prisma`, модель `GenerationJob`).

Все даты — строки ISO 8601 в UTC.

| Поле | Тип | Описание |
|---|---|---|
| `id` | string (UUID) | Идентификатор задания. Им адресуются продолжение, отмена, состояние, отчёт о неудачах и скачивание. |
| `orgId` | string (UUID) | Организация, которой принадлежит выпуск. |
| `documentId` | string (UUID) | Материал, по макету которого идёт выпуск. |
| `format` | `pdf` \| `jpg` | В чём выпускаются документы. Задаётся при запуске и потом не меняется. |
| `status` | `queued` \| `running` \| `done` \| `failed` \| `canceled` | Состояние задания, см. ниже. |
| `total` | number | Сколько строк обещано выпустить. При продолжении пересчитывается под сегодняшний список отмеченных строк. |
| `done` | number | Сколько документов уже создано. Считается по фактам — по файлам с байтами в хранилище, а не приращением счётчика. |
| `failed` | number | По скольким строкам записана причина неудачи. Поимённо — `GET /api/jobs/{jobId}/failures`. |
| `error` | string \| null | Что случилось со всем выпуском, по-русски. Заполняется, когда выпуск остановлен общей бедой, не поставился в очередь или закончился с неудачными строками (`Не удалось создать файлов: N`). Null — сказать нечего. |
| `chunks` | number | На сколько частей пакет разрезан в очереди (по 50 строк). Служебное: по нему части снимаются с очереди при отмене. |
| `attempt` | number | Номер попытки, с единицы. Растёт на каждое продолжение — номер входит в идентификаторы частей в очереди. |
| `createdAt` | string (дата) | Когда задание создано. От него же считается признак «зависло». |
| `startedAt` | string (дата) \| null | Когда воркер взял первую часть. Null — за заданием ещё никто не пришёл. |
| `finishedAt` | string (дата) \| null | Когда задание закрылось — успехом, неудачей или отменой. |

## Состояния

Перечисление `JobStatus` в схеме Prisma:

- `queued` — задание создано, части лежат в очереди, воркер к ним не приступал;
- `running` — воркер взял первую часть; документы создаются;
- `done` — по всем `total` строкам есть исход и хотя бы один документ создан;
- `failed` — выпуск закрыт, но не дал ни одного документа: либо все строки
  упали, либо выпуск остановлен общей бедой (умершее хранилище, упавший
  браузер), либо пакет не удалось поставить в очередь;
- `canceled` — выпуск отменили вручную. Уже созданные документы остаются.

Закрытые состояния — `done`, `failed`, `canceled`; у них заполнено `finishedAt`.

## Признак «зависло»

`GET /api/jobs/{jobId}` добавляет к записи вычисляемое поле `stuck` (boolean).
Оно истинно, когда все четыре условия выполнены разом: `status` — `queued`,
`startedAt` — null, `done` и `failed` — нули, а с `createdAt` прошло 15 минут
и больше (`STUCK_AFTER_MS` в `generation.service.ts`).

Такое задание не идёт медленно, а стоит навсегда: запись о задании коммитится
в базу раньше, чем пакет кладётся в очередь, и моргнувший Redis между этими
шагами оставлял бы вечный прогресс. Зависшее задание принимается
`POST /api/jobs/{jobId}/resume` наравне с упавшим и отменённым. Сервер и сам
раз в пять минут ищет такие задания и поднимает их тем же путём, поэтому
`stuck: true` может рассосаться без вашего участия.

## Что можно делать в каком состоянии

| Состояние | `resume` | `cancel` |
|---|---|---|
| `queued`, `stuck: false` | нет — «Этот выпуск и так идёт» | да |
| `queued`, `stuck: true` | да | да |
| `running` | нет — «Этот выпуск и так идёт» | да |
| `done` | нет — «Этот выпуск уже завершён — продолжать нечего» | нет — «Это задание уже завершено — отменять нечего» |
| `failed` | да | нет |
| `canceled` | да | нет |

Скачивать (`download-options`, `archive`) можно в любом состоянии: отдаются
файлы, созданные к этому моменту.
