# API сервиса «Вручай»

«Вручай» выпускает именные документы: сертификаты, грамоты, дипломы и благодарности.
Вы приносите таблицу участников и макет листа, сервис возвращает готовые PDF — по одному
на человека, с подстановкой имени, склонением по падежам, номером и ссылкой на проверку
подлинности.

API повторяет всё, что делает кабинет, за одним исключением: токен не управляет людьми.
Пригласить сотрудника, сменить чужие права или пароль можно только руками из кабинета —
см. [Аутентификация](authentication.md).

## Базовый адрес

```
https://vruchay.ru/api
```

Все адреса ниже приводятся вместе с префиксом `/api`. Единственное исключение —
проверка живости `/health`, она лежит вне префикса и токена не требует.

Косая черта в конце адреса ничего не меняет: `/api/documents` и `/api/documents/` — один
и тот же маршрут.

## Формат обмена

- Тело запроса и ответа — JSON в UTF-8, заголовок `Content-Type: application/json`.
  Исключения: загрузка файлов (`multipart/form-data`) и выгрузки, отдающие CSV, PDF или ZIP.
- Идентификаторы объектов — UUID.
- Даты — строки ISO 8601 в UTC, например `2026-09-03T10:15:00.000Z`.
- Тексты сообщений об ошибках — русские: они написаны для человека, который будет читать
  их в интерфейсе или в журнале.
- Предел размера тела запроса — 1 МБ. Единственное исключение — подтверждение импорта
  получателей, там предел выше; точное значение указано на странице этого эндпоинта.

## С чего начать

1. Заведите токен в кабинете: **Настройки → Доступ по API**. Полный токен показывается
   один раз, дальше хранится только его хеш.
2. Проверьте связь: `GET /api/auth/me` с заголовком `Authorization: Bearer vru_…`.
3. Пройдите основной путь: документ → получатели → проверка → выпуск → архив.
   Он расписан по шагам в [AGENTS.md](AGENTS.md).

```bash
curl -H "Authorization: Bearer $VRUCHAY_TOKEN" https://vruchay.ru/api/auth/me
```

## Что API не делает

Честнее сказать сразу, чем заставлять искать:

- **Нет пакетного эндпоинта.** Строки получателей добавляются по одной либо целиком
  через разбор файла и подтверждение импорта. Отдельного «создать сто строк одним
  запросом» нет.
- **Нет исходящих вебхуков про выпуск.** О завершении задания узнают опросом
  `GET /api/jobs/{jobId}`. Входящие вебхуки почтового шлюза и платежей к этому
  отношения не имеют — они наши служебные и в этой документации не описаны.
- **Нет постраничной навигации по курсору.** Списки отдаются целиком либо
  с ограничением, указанным на странице конкретного эндпоинта.
- **Токен не управляет сотрудниками.** Приглашения, смена ролей и пароля доступны
  только человеку в кабинете.
