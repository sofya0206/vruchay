# 1.3 Вкладка «Рассылка»: массовая отправка документов

## Как работать

Выполни всё до конца самостоятельно. Вопросов не задавай и подтверждений не жди: на развилке выбирай вариант, который проще для пользователя и меньше трогает чужие файлы, делай его и опиши выбор в описании PR. Пункты со словом «Решение» уже согласованы — не пересматривай.

Сначала прочитай `CLAUDE.md` в корне целиком: Zod-валидация входа, только Prisma с параметризованными запросами, orgId-скоп с 404 вместо 403 для чужих данных, секреты только через env, без ПДн в логах. Правило деплоя: в прод — только после того, как я явно напишу слово «выкатывай», ни по какому другому сообщению.

## Что уже есть

Почта в проекте работает: на сервере `apps/server/src/mail/`, в базе `EmailTemplate`, `Email`, `EmailEvent`, `Sender`, `MailDomain` с проверкой домена. Сегодня рассылка запускается со страницы редактирования материала. Задача — сделать её отдельным разделом, не смешанным ни с редактором, ни с библиотекой шаблонов. Прочитай существующий код почты прежде, чем писать новый: заново отправку не изобретай.

## Что делать

**А. Сценарий.** Выбрать материал (или несколько) → задать получателей → проверить → отправить → видеть журнал. Получатели задаются двумя способами: вручную списком адресов и из уже загруженной таблицы получателей, по которой заодно заполняются данные документа. Второй способ — основной, он опирается на импорт из блока 9, не делай для него второй загрузчик.

**Б. Проверка до отправки.** Тройное превью: сам документ, письмо, страница получателя. Тестовая отправка себе одной кнопкой. Защита от повторной отправки одному и тому же адресу по одному материалу.

**В. Журнал доставки.** Статусы по каждому письму: отправлено, доставлено, прочитано, не доставлено. При недоставке — понятная причина, а не голый код: несуществующий адрес, переполненный ящик, отказ по политике домена получателя. Кнопка «отправить повторно всем недоставленным».

**Г. Юридическое требование к архитектуре — это не пожелание, а деньги.** Держи два раздельных потока отправки. Транзакционный — выдача документа, ссылка, уведомление об истечении срока: согласие на рекламу по ст. 18 ФЗ «О рекламе» не требуется. Маркетинговый — с согласием, отпиской и журналом согласий. **Ловушка: любой рекламный кусок внутри транзакционного письма делает всё письмо рекламным целиком**, штраф по ст. 14.3 КоАП для юрлица от 300 тысяч до миллиона рублей за каждый факт. Разделение должно быть в коде — разные типы писем, разные шаблоны, невозможность подмешать маркетинговый блок в транзакционное письмо, — а не в инструкции для оператора. Напиши на это тест.

## Что в эту задачу НЕ входит

Отложенная отправка по расписанию, черновики партии с выдачей позже, копии на адреса из колонок файла, свой HTML в шаблоне письма. Упомяни в PR как следующую очередь.

## Не трогай

`apps/server/src/generation/`, `apps/web/src/recipients/`, `apps/web/src/validation/`, `apps/web/src/awards/`, `apps/web/src/editor/`, `apps/web/src/documents/`. Навигацию и `apps/web/src/ui/` — зона 1.1.

## Приёмка

- Рассылка живёт отдельным разделом и работает без захода в редактор.
- Оба способа задать получателей работают, из таблицы — на существующем импорте.
- Тестовая отправка себе и тройное превью на месте.
- Журнал показывает причину недоставки словами и позволяет переотправить недоставленные одной кнопкой.
- Тест подтверждает, что рекламный блок нельзя подмешать в транзакционное письмо.
