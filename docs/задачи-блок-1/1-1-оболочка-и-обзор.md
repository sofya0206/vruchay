# 1.1 Информационная архитектура и вкладка «Обзор»

## Как работать

Выполни всё до конца самостоятельно. Вопросов не задавай и подтверждений не жди: на развилке выбирай вариант, который проще для пользователя и меньше трогает чужие файлы, делай его и опиши выбор в описании PR. Пункты со словом «Решение» уже согласованы — не пересматривай.

Сначала прочитай `CLAUDE.md` в корне целиком: Zod-валидация входа, только Prisma с параметризованными запросами, orgId-скоп с 404 вместо 403 для чужих данных, секреты только через env, без ПДн в логах. Правило деплоя: в прод — только после того, как я явно напишу слово «выкатывай», ни по какому другому сообщению.

## Что уже есть в коде (проверено)

После входа пользователь попадает на `/` — это `DocumentsPage`, список материалов. Кроме него в кабинете живут только `/documents/:id` (редактор), `/settings` и `/invoices`. Общей оболочки, шапки и навигации нет вовсе: каждая страница рисует себя сама. Маршруты — в `apps/web/src/App.tsx`. Библиотека компонентов бедная: в `apps/web/src/ui/` только `Button`, `Field`, `Loading`, `InstallHint`. Клиенты API — в `apps/web/src/api/`.

Только что слит блок 9 — ядро выпуска: импорт списков, сопоставление колонок, проверка всех строк до выпуска, склонение ФИО, правила награждения по протоколу, очередь массовой генерации. Всё это работает, но пользователь до него почти не добирается. Ради этого и делается блок 1.

## Разделение зон между параллельными ветками

Одновременно идут четыре задачи блока 1. Чтобы слияние не превратилось в разбор конфликтов:

- **Оболочку, навигацию и `App.tsx` правит только 1.1.** Остальные добавляют РОВНО одну строку маршрута в размеченном комментарием месте и один пункт в список вкладок — больше в этом файле ничего.
- Каждая задача живёт в своей папке под `apps/web/src/` и своей под `apps/server/src/`.
- Общие компоненты в `apps/web/src/ui/` создаёт 1.1. Нужен новый общий компонент — сделай его локально у себя и напиши об этом в PR, в `ui/` не лезь.

## Когда закончишь

1. `pnpm lint && pnpm -r test && pnpm -r build` — всё зелёное.
2. Коммит, пуш ветки, pull request в `main`.
3. В описании PR: что сделано, какие решения принял, что осталось, какие тесты добавлены.
4. PR не мержить, в прод ничего не выкатывать.

## Что делать

Это фундамент блока: остальные три ветки втыкаются в то, что ты сделаешь.

**А. Оболочка кабинета.** Общий макет со шапкой и навигацией по шести разделам: Обзор, Документы, Рассылка, Реестр, Интеграции, Оплата. Настройки в этот список не входят — это отдельная страница со своим блоком задач. Оболочка должна показывать, в каком разделе пользователь сейчас, работать на узком экране и не мигать при переходах.

**Решение по маршрутам:** `/` — Обзор, `/documents` — Документы, `/mailing` — Рассылка, `/registry` — Реестр, `/integrations` — Интеграции, `/billing` — Оплата. Сегодня `/` это список материалов — перенеси его на `/documents` и поставь редирект со старого адреса, чтобы сохранённые ссылки не сломались.

Для разделов, которые делают параллельные ветки, поставь заглушки с честным текстом «раздел в работе» и **оставь в `App.tsx` размеченный комментарием блок**, куда они добавят свои маршруты одной строкой. Заглушки Интеграций и Оплаты оставь как есть — эти задачи ещё не начаты.

**Б. Вкладка «Обзор».** Рабочий стол, а не витрина. Три части:

1. Метрики: сколько документов выпущено всего и за текущий месяц, сколько осталось на бесплатной пробе, сколько писем ушло. Данные бери из того, что уже есть — `files` с `kind: generated`, `generation_jobs`, `emails`. Новых таблиц не заводи.
2. Быстрые действия, ведущие прямо в ядро блока 9: «Выпустить документы по списку», «Загрузить протокол соревнований», «Создать материал». Это главный смысл экрана — путь от входа до выпуска в три клика.
3. Последние мероприятия: свежие материалы и задания на выпуск с их состоянием, отсюда же переход в реестр и в редактор.

**В. Пустое состояние.** Организация, которая только зарегистрировалась, должна видеть не нули, а понятный первый шаг. Сегодня это главная точка отвала — отнесись к ней серьёзнее, чем к метрикам.

**Г. Серверная часть.** Один эндпоинт сводки в новой папке `apps/server/src/overview/`. Считай агрегатами в одном-двух запросах, не выбирай строки в память. orgId из сессии, чужое — 404.

## Не трогай

`apps/web/src/recipients/`, `apps/web/src/validation/`, `apps/web/src/awards/`, `apps/web/src/editor/`, `apps/server/src/generation/` — это ядро, оно только что слито и в блоке 1 его никто не переписывает. Папки `mail/` на вебе и на сервере — зона задачи 1.3.

## Приёмка

- После входа пользователь видит рабочий стол с шестью разделами, а не список материалов.
- От входа до начала выпуска документов — не больше трёх кликов.
- Старые ссылки на `/` и `/documents/:id` продолжают работать.
- Новая организация видит осмысленный первый шаг, а не нули.
- В `App.tsx` есть размеченное место для маршрутов параллельных веток.
