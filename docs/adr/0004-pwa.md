# ADR-0004. Установка на устройство и уведомления (PWA)

Статус: **принято** · Дата: 31.07.2026

## Контекст

Нужно, чтобы пользователь мог поставить сервис на телефон или компьютер как приложение
и получать уведомления — о готовности пакета сертификатов, о завершении рассылки,
о недоставленных письмах.

Аудитория — секретари федераций и организаторы мероприятий. Они запускают генерацию
на сотни документов и не хотят держать вкладку открытой; уведомление «300 из 300 готово,
рассылка завершена, 4 письма не доставлены» — это ровно тот момент, когда сервис
экономит им время.

## Решение: PWA, без нативных приложений

Отдельные приложения для iOS и Android не делаем: два магазина, ревью, сертификаты
разработчика и отдельные релизные циклы — неоправданно для сервиса, где вся работа
происходит в большом редакторе и таблице. PWA даёт установку на устройство и push
той же кодовой базой.

### Состав

**Установка.** `manifest.webmanifest`: имя, иконки (192, 512, maskable), `display: standalone`,
`start_url: /`, тема. Плагин `vite-plugin-pwa` генерирует манифест и service worker в сборке.

**Service worker.** Стратегия — `injectManifest`, свой воркер, потому что нам нужен не только
кэш, но и обработка push. Кэшируем оболочку приложения и шрифты; API-запросы всегда идут
в сеть (нельзя показывать устаревший список документов). Офлайн-режима для редактора
не делаем — генерация всё равно серверная.

**Push-уведомления.** Web Push по стандарту VAPID:
- ключи VAPID в переменных окружения (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`), приватный —
  только на сервере;
- таблица `push_subscriptions` (`orgId`, `userId`, `endpoint` уникальный, `p256dh`, `auth`,
  `userAgent`, `createdAt`, `lastSeenAt`);
- отправка из воркера через `web-push`; на 404/410 от push-сервиса подписка удаляется;
- разрешение запрашиваем **не при первом заходе**, а в момент, когда пользователь запускает
  первую длительную генерацию — там польза очевидна и согласие получаем осознанное.

**События, о которых уведомляем:** генерация пакета завершена; рассылка завершена (со сводкой
доставленных и недоставленных); задание упало с ошибкой. Всё остальное — не уведомляем,
чтобы не приучать отключать разрешение.

### Ограничения, о которых нужно помнить

- **iOS**: Web Push работает только для сайтов, **добавленных на домашний экран**, начиная
  с iOS 16.4. Пока приложение открыто как обычная вкладка Safari, уведомления не придут.
  В интерфейсе показываем подсказку «Поделиться → На экран "Домой"» для пользователей iOS.
- **Разрешение на уведомления запрашивается только по жесту пользователя** и только по HTTPS.
  На проде это выполняется; локально работает на `localhost`.
- Иконки и manifest должны отдаваться с правильными заголовками — Caddy это делает,
  но при смене домена manifest`start_url` обновляется вместе с `PUBLIC_URL`.

### Безопасность

- Эндпоинты подписки (`POST /api/push/subscribe`, `DELETE /api/push/subscribe`) требуют
  сессии; подписка жёстко привязывается к `userId` и `orgId` из сессии, а не из тела запроса.
- В тело push-уведомления **не кладём персональные данные** — только «Готово 300 из 300»
  и идентификатор задания. Имена участников в уведомление не попадают: содержимое push
  проходит через сторонний push-сервис (FCM, APNs, Mozilla) и уходит за пределы контура.
- Service worker обслуживает только собственное происхождение; сторонние скрипты в нём
  запрещены.

## Когда делаем

Устанавливаемость (manifest + service worker) — вместе с Фазой 1, это несколько часов.
Push-уведомления — в Фазе 2, сразу после появления фоновой генерации: раньше уведомлять не о чем.
