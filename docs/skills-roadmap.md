# Какие навыки подключаем на каждом этапе

Чтобы не переделывать: перед каждым крупным куском работы включаем профильный навык,
а не пишем «как получится». Ниже — что и когда.

## Уже применено

| Этап | Навык | Что дал |
|---|---|---|
| Интерфейс (Фаза 1) | `artifact-design` | Дизайн-система: палитра из предметной области (лавр и латунь вместо дефолтного индиго), пара шрифтов, обе темы через токены, состояния формой и цветом |
| Весь код | правила Secure by Design из `CLAUDE.md` | Проверка принадлежности объекта организации, валидация на бэкенде, тип файла по сигнатуре |

## Дальше по фазам

### Фаза 2 — получатели и генерация PDF
- **`xlsx`** — импорт списков участников из Excel: разбор кривых таблиц, где шапка не в первой
  строке, объединённые ячейки, лишние колонки. Это ровно то, что присылают федерации.
- **`pdf`** — проверка готовых файлов: извлечение текста из сгенерированного PDF, чтобы автотест
  ловил «кракозябры» вместо кириллицы, и склейка пакета документов в один файл для печати.
- **`simplify`** — после того как воркер заработает: пройтись по коду генерации, убрать
  дублирование и лишние абстракции, пока их немного.

### Фаза 3 — почта
- **`security-review`** — перед первой боевой рассылкой: письма содержат персональные данные,
  а вебхуки провайдера — публичный эндпоинт.

### Фаза 4 — Тильда и публичные формы
- **`security-review`** обязательно: это единственная часть системы, доступная из интернета
  без авторизации. Проверяем анти-абьюз, одноразовые коды, ограничение по доменам.
- **`artifact-design`** — оформление модального окна и формы на стороне Тильды: это первое,
  что видит участник, и оно должно выглядеть как часть сайта федерации.

### Фаза 5 — запуск
- **`doc-coauthoring`** — политика обработки персональных данных, оферта, договор-поручение:
  структурированные документы, где важна полнота разделов, а не красота.
- **`docx`** — те же документы в формате Word: юристу и бухгалтерии федерации нужен именно он.
- **`security-review`** — финальный проход перед боем.

### Фаза 6+ — вторая очередь и продажи
- **`dataviz`** — статистика рассылок и выдач в личном кабинете: доставляемость, открытия,
  динамика по мероприятиям. Без этого навыка получаются нечитаемые графики.
- **`marketing:draft-content`** и **`marketing:competitive-brief`** — лендинг, коммерческое
  предложение для ВФЛА, сравнение с ГрамотаДелом.
- **`product-management:write-spec`** — спецификации крупных фич (импорт протоколов
  соревнований, правила награждения по местам), чтобы не проектировать их на ходу.
- **`claude-api`** — если добавим подсказки на основе моделей: например, автоматическую
  расстановку блоков по загруженному фону.

## Постоянные

- **`/code-review`** — запускается вами, не мной: перед слиянием крупных веток.
- **`simplify`** — раз в фазу, по изменённому коду.
- **`schedule`** — когда понадобятся регулярные задачи: ночные бэкапы уже на cron,
  но отчёты и напоминания о продлении домена удобнее повесить сюда.
