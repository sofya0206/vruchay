# Поисковая оптимизация посадочной страницы

## Главная проблема: роботу приходит пустая страница

Приложение отрисовывается в браузере. В HTML, который получает поисковый
робот, лежит только `<div id="root"></div>` — весь текст посадочной
появляется после выполнения JavaScript.

Google научился исполнять скрипты и чаще всего такую страницу разберёт.
**Яндекс делает это плохо и непредсказуемо**, а он и есть наш рынок:
федерации, спортшколы и организаторы ищут в Яндексе.

Пока это не решено, остальные работы по SEO бессмысленны: нельзя
оптимизировать текст, которого робот не видит.

### Решение: предварительная отрисовка при сборке

Не переезд на серверную отрисовку — для посадочной это избыточно. Нужен
шаг сборки, который открывает собранное приложение в браузере, дожидается
отрисовки и сохраняет готовый HTML для публичных адресов: `/`, `/privacy`,
`/oferta`.

Playwright для этого уже стоит — тот же браузер, что печатает документы.
Новых зависимостей не требуется.

Что важно не сломать: кабинет предварительно отрисовывать нельзя и не нужно —
он за входом. Речь только о публичных страницах.

## Что ещё отсутствует

| Что | Зачем | Состояние |
|---|---|---|
| `description` | Строка под ссылкой в выдаче. Без неё поисковик берёт случайный кусок текста | нет |
| Open Graph и `twitter:card` | Как выглядит ссылка в Телеграме и мессенджерах. Половина переходов в B2B идёт из пересылок | нет |
| `canonical` | Защита от склейки `www` и адресов с параметрами | нет |
| `robots.txt` | Закрыть от индексации кабинет, страницу печати и API | нет |
| `sitemap.xml` | Список публичных адресов | нет |
| Разметка schema.org | `Organization`, `Product` с ценами, `FAQPage` по нашим вопросам. Даёт расширенный сниппет в выдаче | нет |
| Яндекс.Вебмастер | Подтверждение прав, отслеживание индексации | нет |
| Яндекс.Метрика | Откуда приходят и куда уходят | нет |

`FAQPage` стоит отдельного упоминания: у нас восемь настоящих вопросов
с ответами, и это ровно тот случай, ради которого разметка придумана.

## Порядок работ

1. **Предварительная отрисовка** — без неё остальное не имеет смысла.
2. Мета-теги и Open Graph, разные для каждой публичной страницы.
3. `robots.txt` и `sitemap.xml`.
4. Разметка schema.org: `Organization`, `Product`, `FAQPage`.
5. Подтверждение прав в Яндекс.Вебмастере, отправка карты сайта.
6. Метрика.
7. Подбор запросов и правка текстов под них — **последним**, когда есть
   что индексировать.

## Подбор запросов

Нужен доступ к Вордстату. MCP-сервер Яндекса у владельца был, но папка
`~/Downloads/ИИ/yandex-mcp` удалена — требуется установка заново.

Гипотезы до проверки частотности, от самых денежных к общим:

- «сервис рассылки сертификатов участникам»
- «программа для печати грамот по списку»
- «генератор дипломов из excel»
- «именные сертификаты онлайн массово»
- «сертификат участника соревнований шаблон»
- «электронные грамоты для спортсменов»

Проверять их надо по частотности **и по тому, что уже в выдаче**: если по
запросу стоят шаблоны для Word, значит человек ищет картинку, а не сервис,
и такой запрос нам не нужен, сколько бы он ни весил.

## Чего не делаем

**Не пишем текст под запросы в ущерб смыслу.** Страница построена на
проверяемых утверждениях; подмешивать в неё «грамоты купить недорого»
означает испортить то, ради чего она работает.

**Не заводим блог до запуска.** Статьи имеют смысл, когда сервис работает
и есть что показывать; до этого они отнимают время у более важного.
