# Сертификат в курсе одной кнопкой

Для страниц внутри личного кабинета — курсов, закрытых разделов, любых
мест, куда человек уже вошёл. Он ничего не набирает: имя и почта
подставляются из его учётной записи, ему остаётся проверить их
и нажать одну кнопку.

## Что вставить на страницу

**Одна вставка, и в шаблон сайта лезть не нужно.** В кабинете, в разделе
«Выдача документов на сайте», выберите свою площадку — код подставится
готовым, с вашим токеном и кодом документа. Нажмите «Копировать код»
и вставьте туда, где должна быть кнопка.

Для Тильды и своего сайта это выглядит так:

```html
<div data-vruchay-certificate
     data-doc-id="КОД-ДОКУМЕНТА"
     data-label="Получить сертификат"></div>
<link rel="stylesheet" href="https://vruchay.ru/api/v1/tilda-css/ВАШ-ТОКЕН">
<script src="https://vruchay.ru/api/v1/tilda-js/ВАШ-ТОКЕН"></script>
```

Для WordPress и Битрикса код другой — он сам достаёт имя и почту
вошедшего (см. «Другие площадки» ниже).

Никаких форм собирать не нужно: кнопку и окно нарисует сам скрипт.
От повторной загрузки он защищён, поэтому двух кнопок из-за двух блоков
на одной странице не будет.

## Что увидит человек

1. Кнопку «Получить сертификат».
2. Окно **«Проверьте данные»** — фамилия и почта уже вписаны, взяты
   из его учётной записи. Плюс галочка согласия с понятным текстом.
3. После нажатия «Всё верно» — **«Готово»**: кнопка скачивания, кнопки
   «ВКонтакте», «Telegram», «WhatsApp», «Скопировать ссылку» и ссылка
   на страницу проверки подлинности.
4. Письмо с документом во вложении приходит на почту.

Шаг с проверкой данных убирать нельзя, и он сделан нарочно: сервис
впечатывает в наградной документ то, что подставилось, а исправлять
фамилию в уже выданном документе куда дороже, чем прочитать её сейчас.

## Настройки — каждая отдельно

В карточке интеграции:

| Настройка | По умолчанию | Что делает |
|---|---|---|
| Подставлять данные из кабинета | включено | берёт имя и почту у вошедшего участника |
| Разрешить правку данных | включено | можно исправить опечатку и сменить адрес доставки |
| Кнопки «поделиться» | включено | ВКонтакте, Telegram, WhatsApp, копирование ссылки |
| Ссылка на проверку подлинности | выключено | появляется, только если проверка включена у документа |
| Окно скачивания | включено | кнопка «Скачать» в окне успеха |
| Отправлять письмом | включено | документ во вложении на указанную почту |
| Один документ в руки | включено | см. ниже |
| Подтверждение по коду | выключать для курсов | шестизначный код на почту перед выдачей |

**Про подтверждение по коду.** Внутри личного кабинета оно избыточно:
до страницы дошёл тот, кто уже вошёл. Оставьте его выключенным — это
и есть весь смысл сценария «нажал и получил». Для **открытых** страниц,
куда попадает кто угодно, наоборот, включайте.

## Один документ в руки

Заявка несёт два разных адреса, и это отвечает на два разных вопроса:

- **куда прислать** — его человеку можно разрешить менять;
- **кто это** — адрес учётной записи, подставленный кабинетом; человек
  его не набирал.

Однократность считается по второму. Поэтому правку адреса можно смело
оставлять включённой: прислать документ на другую почту получится,
а получить второй сертификат — нет.

Проверено на живой базе:

| Что пробовали | Результат |
|---|---|
| Тот же участник, другой адрес доставки | отказ, отдаём выданное |
| Тот же участник, другой регистр адреса | отказ |
| Другой участник | выдача |
| Незавершённая заявка того же участника | не мешает получить |

Защита стоит **в самой базе** двумя уникальными индексами, а не только
в коде: два одновременных нажатия «получить» не проскочат мимо проверки.

Незавершённые заявки не учитываются нарочно: человек мог закрыть вкладку
на полпути, и это не должно навсегда лишать его документа.

## Чего этот сценарий не даёт

Данные приходят из браузера, поэтому сами по себе доказательством
личности не служат. Участник курса, разбирающийся в устройстве страниц,
может запросить документ на имя другого участника — один раз, потому
что дальше сработает однократность.

Для сертификата о прохождении курса это несущественно: страница
и так за логином, а посторонний до неё не доходит. Если выдаёте что-то,
где цена ошибки выше, — включите подтверждение по коду.

## Другие площадки

В кабинете, в карточке интеграции, выберите площадку — код для вставки
подставится готовым: **Тильда, WordPress, 1С-Битрикс, свой сайт.**

Вставка **одна**, и лезть в шаблон сайта не нужно: подключение скрипта
идёт тем же куском, что и сам блок. От повторной загрузки скрипт
защищён, поэтому двух кнопок из-за двух блоков на странице не будет.

Отличается только то, откуда берутся имя и почта вошедшего:

| Площадка | Источник |
|---|---|
| Тильда | поля `ma_name` и `ma_email` — их кладёт сам личный кабинет |
| WordPress | короткий код `[vruchay_certificate]`, данные из `wp_get_current_user()` |
| 1С-Битрикс | `$USER->GetFirstName()`, `GetLastName()`, `GetEmail()` |
| Свой сайт | атрибуты `data-name` и `data-email` — подставьте своим шаблоном |

Данные подставляются **шаблоном на стороне сервера**, а не читаются
из браузера. Это надёжнее: недокументированные объекты у каждой площадки
свои, меняются от версии к версии и молча исчезают, а `$USER` в Битриксе
и `wp_get_current_user()` в WordPress описаны в справочниках и делают
ровно то, что написано. Имена методов сверены с их документацией.

Оба готовых куска проверяют, что человек вошёл, и экранируют всё, что
попадает в разметку: имя человек заполняет сам в своём профиле, и без
экранирования это была бы дыра на сайте клиента. В WordPress для этого
`esc_attr` и `esc_url`, в Битриксе — `htmlspecialcharsbx` (не
`htmlspecialcharsEx`: тот работает по чёрному списку, и сама Битрикс
советует его избегать).

Если площадка ничего не сообщила — поля просто останутся пустыми,
и человек заполнит их сам. Кнопка работает всегда.

Для новой площадки нужно добавить только её способ отдавать данные
вошедшего: работы на несколько строк.
