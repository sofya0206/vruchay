# Вручай — сервис цифровых документов

Массовое создание, выдача и проверка именных документов: грамоты,
сертификаты, дипломы. Загружаешь список людей, выбираешь макет —
сервис выпускает PDF, рассылает по почте и даёт каждому документу
страницу проверки по QR.

Сайт: https://vruchay.ru. Данные и серверы — в РФ (152-ФЗ), Selectel,
аттестованная зона.

## Стек

TypeScript · React 19 + Vite + Tailwind · NestJS 11 (Fastify) · Prisma +
PostgreSQL · BullMQ + Redis · Playwright (PDF) · Docker + Caddy.

## Структура

- `apps/web` — интерфейс (кабинет, редактор, посадочная)
- `apps/server` — API и воркер генерации/рассылки
- `packages/shared` — общие типы и схема макета (контракт редактор ⇄ PDF)
- `docs/` — решения (ADR), инструкции, бизнес-документы

## Запуск локально

```bash
pnpm install
docker compose -f docker-compose.dev.yml up -d   # postgres, redis, minio, mailpit
cp .env.example apps/server/.env
pnpm --filter @gramota/server prisma:migrate
pnpm dev                                          # server:3000 + web:5173
```

Веб: http://localhost:5173 · Письма: http://localhost:8025 · MinIO: http://localhost:9001

Перед коммитом: `pnpm lint && pnpm -r test && pnpm -r build`.

Часть тестов работает с настоящим Chromium и потому требует установленных
браузеров Playwright. В обычный прогон они не входят — запускаются флагом:

```bash
CHROMIUM_TESTS=1 pnpm --filter @gramota/server test   # сверка измерения текста
CHROMIUM_TESTS=1 pnpm --filter @gramota/web test      # выпущенный PDF и заставка
```

Первым проверяется, что мы не обещаем «влезет» там, где текст обрежется:
измерение по метрикам шрифтов сверяется с браузером. Нужны шрифты
в `apps/web/public/fonts`. Гонять после правок метрик и вёрстки листа.

Второй — единственная проверка, которая смотрит на готовый PDF пикселями:
печатает страницу так же, как воркер, растрирует файл и сравнивает
с эталоном. Она закрывает целый класс бед, которые не видит ни один
другой тест, — что-нибудь непрозрачное поверх листа. Гонять после правок
`apps/web/index.html`, точки входа и страницы печати. Растрирование берёт
просмотрщик PDF из полноценного Chromium: в headless shell его нет, и без
`PLAYWRIGHT_CHANNEL` проверка сама поднимет канал `chromium`.

Локально может понадобиться `PLAYWRIGHT_CHANNEL=chrome`, если браузеры
Playwright не скачаны.

Отдельно от них — проверки против настоящей базы. Пока такая одна: условие
частичного уникального индекса писем живёт в SQL миграции, и подменённая
Prisma о нём ничего сказать не может.

```bash
DB_TESTS=1 DATABASE_URL=postgresql://… pnpm --filter @gramota/server test
```

Базе нужны накатанные миграции, и на боевую её направлять незачем: тест
работает в своей организации и всё за собой убирает, но проверять такое
положено на пустой. Гонять после правок миграций и логики рассылки.
