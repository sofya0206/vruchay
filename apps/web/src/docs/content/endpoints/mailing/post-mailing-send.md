# POST /api/mailing/send

Ставит письма в очередь по каждому из выбранных материалов — до двадцати за вызов, по письму на материал каждому получателю. Ответ приходит сразу после постановки; отправка асинхронная: воркер шлёт не быстрее пяти писем в секунду и делает до пяти попыток с нарастающей задержкой (первая — 15 с). Что с письмами дальше — `GET /api/mailing/log`.

Отличие от `POST /api/mail/send/{documentId}`: там один материал, только транзакционный поток и только отмеченные строки таблицы, а повторный вызов подряд роняет всю отправку. Здесь материалов несколько, поток выбирается явно, получателей можно задать списком адресов, а дубли пропускаются молча — второе нажатие «Отправить» не удвоит письма и не сломает рассылку.

Расчёт получателей тот же, что в `POST /api/mailing/audience`; проверить состав лучше заранее. Рекламная рассылка уходит только тем, кто дал согласие; письмо дополняется пометкой «Реклама», рекламодателем и ссылкой отписки.

Если у шаблона материала нет своего отправителя, письма идут с общего адреса сервиса, и перед постановкой проверяется его лимит: не больше `SHARED_DOMAIN_BATCH_LIMIT` (по умолчанию 300) писем за раз и `SHARED_DOMAIN_DAILY_LIMIT` (по умолчанию 500) за сутки на организацию. Со своего подтверждённого домена лимита нет.

Материалы обрабатываются по очереди, и отказ по третьему материалу не отменяет уже поставленные письма по первым двум: ответа в этом случае не будет вовсе, а часть писем уже уйдёт. Действие необратимое и пишется в журнал аудита (`mailing.send`) — с потоком, источником и числом писем по каждому материалу.

## Запрос

Тело — строгая схема, лишние поля запрещены.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| documentIds | string[] (UUID) | да | Материалы, 1–20 |
| kind | `transactional` \| `marketing` | да | Поток письма; шаблон каждого материала ищется по нему же |
| source | `table` \| `manual` | да | Получатели из отмеченных строк таблицы или из списка адресов |
| emails | string | при `source: "manual"` | Список адресов одной строкой, до 60 000 символов; разделители — перевод строки, запятая, точка с запятой, пробел |

```json
{
  "documentIds": [
    "9e8d7c6b-5a4f-4e3d-2c1b-0a9f8e7d6c5b",
    "1c2d3e4f-5a6b-4c7d-8e9f-0a1b2c3d4e5f"
  ],
  "kind": "transactional",
  "source": "table"
}
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| results | array | По записи на материал |
| results[].documentId | string (UUID) | Материал |
| results[].title | string | Название материала |
| results[].queued | number | Сколько писем поставлено в очередь по этому материалу |
| results[].skipped | array | Пропущенные: `{name, email, reason}` |
| queued | number | Сумма по всем материалам |

```json
{
  "results": [
    {
      "documentId": "9e8d7c6b-5a4f-4e3d-2c1b-0a9f8e7d6c5b",
      "title": "Грамоты участникам",
      "queued": 47,
      "skipped": [
        { "name": "Кузнецов Олег", "email": "", "reason": "нет адреса" }
      ]
    },
    {
      "documentId": "1c2d3e4f-5a6b-4c7d-8e9f-0a1b2c3d4e5f",
      "title": "Сертификаты судей",
      "queued": 12,
      "skipped": []
    }
  ],
  "queued": 59
}
```

`queued` — число действительно созданных писем. Адреса, которым по этому материалу и потоку уже писали, отсеиваются расчётом и попадают в `skipped`; те, что проскочили в промежуток между расчётом и записью (два быстрых нажатия подряд), отсекает уникальный индекс базы — они выпадают молча, и в `skipped` их нет.

## Ошибки

| Код | Когда |
|---|---|
| 400 | `documentIds` пуст: «Выберите хотя бы один материал»; больше двадцати: «За раз можно разослать не больше двадцати материалов»; элемент не UUID: «Invalid UUID» |
| 400 | `source: "manual"` без адресов: «Укажите хотя бы один адрес» |
| 400 | `kind` или `source` не из списка; лишнее поле в теле: «Unrecognized key: "…"» |
| 400 | У материала нет шаблона этого потока: «Для материала «Грамоты участникам» письмо не настроено» |
| 400 | Поток шаблона не совпал с потоком отправки: «Рекламный текст нельзя отправить письмом о выдаче документа: такое письмо целиком считается рекламой» / «Для рекламной рассылки нужен рекламный текст письма, а не письмо о выдаче документа» |
| 400 | У рекламного шаблона нет рекламодателя: «Укажите рекламодателя: по закону получатель должен видеть, чья это реклама» |
| 400 | Отправитель шаблона удалён: «Отправитель не найден» |
| 400 | Домен отправителя не подтверждён: «Домен example.ru не подтверждён — отправка невозможна» |
| 400 | Почта не настроена вовсе: «Отправка писем не настроена — обратитесь в поддержку» |
| 400 | Превышен разовый лимит общего домена: «За один раз с общего адреса уходит не больше 300 писем, а отмечено 350. Разбейте на несколько рассылок или подключите свой домен в настройках — со своего домена ограничения нет.» |
| 400 | Превышен суточный лимит общего домена: «За сутки с общего адреса уходит не больше 500 писем: сегодня уже отправлено 480, осталось 20. Подключите свой домен в настройках — со своего домена ограничения нет, и письма вызывают больше доверия.» |
| 401 | Нет токена или сессии |
| 404 | Материала нет, он удалён или чужой: «Материал не найден» |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/mailing/send" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"documentIds":["'"$DOCUMENT_ID"'"],"kind":"transactional","source":"manual","emails":"ivanova@example.com, petrov@example.com"}'
```
