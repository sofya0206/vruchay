# POST /api/mailing/test

Отправляет письмо по сохранённому шаблону на адрес того, кто вошёл, — чтобы посмотреть на него своими глазами. Адрес берётся из сессии, а не из запроса: «проверочная отправка» на чужой адрес была бы рассылкой без согласия, только названной иначе.

Отдельного запрета для токена API здесь нет, но **по токену отправлять некуда**: у входа по токену адреса нет (он пустой), и запрос упирается в ошибку почтового шлюза. Вызывать имеет смысл только из кабинета, по cookie-сессии — поэтому и пример ниже с cookie.

Письмо идёт мимо очереди и мимо журнала доставки: в `GET /api/mailing/log` оно не появится, состояний у него нет. Тема получает приставку `[Проверка]`, переменные подставляются из первой строки таблицы материала, вложением идёт выпущенный по ней файл. Если шаблон обещает вложение, а файла по первой строке ещё нет, письмо всё равно уйдёт — с предупреждающей врезкой вверху. У рекламного письма ссылка отписки в проверочном письме ведёт в никуда намеренно: отписываться не от чего.

Частота ограничена: 5 запросов в минуту на организацию. Превышение возвращает `400`, а не `429`, — это не общий ThrottleGuard, а отдельный счётчик раздела.

## Запрос

Тело — строгая схема, лишние поля запрещены.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| documentId | string (UUID) | да | Материал организации (не удалённый) |
| kind | `transactional` \| `marketing` | да | Поток; шаблон ищется по нему же |

```json
{
  "documentId": "9e8d7c6b-5a4f-4e3d-2c1b-0a9f8e7d6c5b",
  "kind": "transactional"
}
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| to | string | Адрес, на который ушло письмо (адрес вошедшего) |
| title | string | Название материала |
| attached | boolean | Было ли вложение |

```json
{
  "to": "director@example.ru",
  "title": "Грамоты участникам",
  "attached": true
}
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | `documentId` не UUID: «Invalid UUID»; `kind` не из списка; лишнее поле: «Unrecognized key: "…"» |
| 400 | Шаблона этого потока нет: «Сначала сохраните письмо» |
| 400 | Слишком часто: «Слишком часто. Подождите N секунд и попробуйте снова» |
| 400 | Почта не настроена: «Отправка писем не настроена — обратитесь в поддержку» |
| 401 | Нет токена или сессии |
| 404 | Материала нет, он удалён или чужой: «Материал не найден» |
| 500 | Шлюз не принял письмо — в том числе когда вход был по токену API и адрес получателя пуст |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/mailing/test" \
  -b cookies.txt \
  -H "Content-Type: application/json" \
  -d '{"documentId":"'"$DOCUMENT_ID"'","kind":"transactional"}'
```
