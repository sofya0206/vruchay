# POST /api/mailing/resend

Ставит новые письма вместо недоставленных по одному материалу: берутся все письма в состояниях `bounced` и `failed`, по каждому адресу — последняя попытка. Прежние записи не трогаются и остаются в журнале: он обязан помнить, что первая попытка была и чем кончилась.

Кого пропускаем: адреса, по которым после провала письмо уже переотправлялось и держится живым (`queued`, `sent`, `delivered`, `opened`); адреса с безнадёжной причиной — несуществующий ящик, отказ по правилам домена, домен не принимает почту (`problem.retryable: false` в `GET /api/mailing/log`); обезличенные адреса, у которых после срока хранения стёрт адрес участника, — таких в ответе не видно вовсе. Безнадёжные возвращаются в `skipped` с той же формулировкой, что и в журнале: чинить их надо в таблице получателей, а не повтором.

Поток считается отдельно: недоставленное рекламное письмо не закрывается ушедшим письмом о выдаче документа и наоборот. Новое письмо наследует у прошлой попытки поток, строку, шаблон, файл и тему. Два нажатия подряд не удвоят письма — дубли отсекает уникальный индекс. Отправка асинхронная, как и в `POST /api/mailing/send`. Действие пишется в журнал аудита (`mailing.resend`).

## Запрос

Тело — строгая схема, лишние поля запрещены.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| documentId | string (UUID) | да | Материал организации (не удалённый) |

```json
{ "documentId": "9e8d7c6b-5a4f-4e3d-2c1b-0a9f8e7d6c5b" }
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| title | string | Название материала |
| queued | number | Сколько писем поставлено заново |
| skipped | array | Безнадёжные адреса: `{name, email, reason}`; `name` всегда пустая строка — берётся адрес из письма, а не строка таблицы |

```json
{
  "title": "Грамоты участникам",
  "queued": 4,
  "skipped": [
    {
      "name": "",
      "email": "petrov@example.com",
      "reason": "Такого адреса не существует"
    }
  ]
}
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | `documentId` не UUID: «Invalid UUID»; лишнее поле в теле: «Unrecognized key: "…"» |
| 401 | Нет токена или сессии |
| 404 | Материала нет, он удалён или чужой: «Материал не найден» |

Проверок отправителя, потока и лимитов общего домена здесь нет: письмо уже было создано раньше, повтор его не пересоздаёт заново, а копирует.

## Пример

```bash
curl -X POST "https://vruchay.ru/api/mailing/resend" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"documentId":"'"$DOCUMENT_ID"'"}'
```
