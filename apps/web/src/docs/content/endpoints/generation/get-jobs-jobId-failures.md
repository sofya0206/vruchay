# GET /api/jobs/{jobId}/failures

Поимённый разбор неудач задания: по каким строкам документ не создался и
почему. Счётчик `failed` в записи задания говорит «ошибок 12», но по нему
не понять даже, пропали это строки из таблицы или не отрисовались документы,
— здесь ровно это и написано.

Список отдаётся в порядке появления, не больше 200 записей. Постраничности нет:
если неудач больше двухсот, остальные через API не достать.

Причины стираются при продолжении выпуска: `POST /api/jobs/{jobId}/resume`
удаляет все прежние записи, потому что строка либо уже стала файлом, либо будет
напечатана заново. Поэтому забирайте отчёт до продолжения.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `jobId` | UUID (путь) | да | Идентификатор задания |

Тела нет.

## Ответ

`200 OK` — массив; пустой, если неудач нет.

| Поле | Тип | Описание |
|---|---|---|
| `rowId` | string (UUID) | Строка таблицы получателей, по которой не вышло |
| `name` | string | Имя из колонки `name` этой строки. Если строки в таблице больше нет — `Строки больше нет в таблице` |
| `reason` | string | Причина по-русски |

```json
[
  {
    "rowId": "9e8d7c6b-5a4f-4e3d-8c2b-1a0f9e8d7c6b",
    "name": "Иванова Мария Петровна",
    "reason": "Не загрузились шрифты макета"
  },
  {
    "rowId": "0f1e2d3c-4b5a-4968-8778-695a4b3c2d1e",
    "name": "Строки больше нет в таблице",
    "reason": "Строку убрали из таблицы, пока шёл выпуск"
  }
]
```

Набор причин закрытый (`render-failure.ts`): `На сервере кончилось место`,
`Браузер, который печатает документы, не удалось запустить`,
`Браузер, который печатает документы, аварийно завершился`,
`Не загрузились шрифты макета`, `Хранилище файлов не отвечает`,
`Страница документа не успела отрисоваться`, `База данных не отвечает`,
`Документ не удалось создать` (причина не опознана) и
`Строку убрали из таблицы, пока шёл выпуск`.

Часть причин считается общей бедой: если подряд падают две строки с такой
причиной (или пять подряд с неопознанной), выпуск останавливается целиком —
об этом скажет поле `error` в записи задания.

## Ошибки

| Код | Когда |
|---|---|
| 400 | `Некорректный идентификатор` — `jobId` не UUID |
| 401 | Нет токена или сессии |
| 404 | `Задание не найдено` — нет такого или оно чужой организации |

## Пример

```bash
curl "https://vruchay.ru/api/jobs/$JOB_ID/failures" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN"
```
