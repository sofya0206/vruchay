# POST /api/documents/{id}/generate

Заводит задание на выпуск и ставит его в очередь. Выпускаются отмеченные
(`checked`) строки таблицы получателей — по одному документу на строку, с теми
данными, что есть в строке на момент печати.

Выпуск асинхронный. Ответ приходит сразу и означает только «задание принято»:
`status` в нём — `queued`, `done` — ноль, файлов ещё нет. Документы создаёт
отдельный воркер, пакет разрезан на части по 50 строк, и порядок в очереди
зависит от размера пакета — маленькие идут раньше больших. За ходом дела
следите опросом `GET /api/jobs/{jobId}`, пока `status` не станет одним из
закрытых (`done`, `failed`, `canceled`).

По одному материалу одновременно идёт только один выпуск, а вся организация
может держать в очереди не больше `ORG_ACTIVE_JOBS` пакетов (по умолчанию 3).
На бесплатном тарифе действует потолок в `FREE_DOCUMENT_LIMIT` документов
(по умолчанию 50) на организацию за всё время; проверяется он до постановки
задания, поэтому об исчерпанной пробе вы узнаете здесь, а не на сорок седьмом
документе из пятидесяти.

Тело обязательно: без него схема не находит объект и запрос отклоняется. Чтобы
выпустить в PDF, достаточно `{}`.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `id` | UUID (путь) | да | Идентификатор материала |

Тело:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `format` | `pdf` \| `jpg` | нет | В чём выпускать. По умолчанию `pdf`. JPEG — снимок страницы целиком, качество 92; электронную подпись он не носит |

```json
{ "format": "pdf" }
```

## Ответ

`201 Created` — созданное задание, см.
[reference/generation-job.md](../../reference/generation-job.md).

```json
{
  "id": "5c8f1a2b-3d4e-4f50-8a6b-7c8d9e0f1a2b",
  "orgId": "1a2b3c4d-5e6f-4708-9a0b-1c2d3e4f5a6b",
  "documentId": "b1c2d3e4-f5a6-4b7c-8d9e-0f1a2b3c4d5e",
  "format": "pdf",
  "status": "queued",
  "total": 128,
  "done": 0,
  "failed": 0,
  "error": null,
  "chunks": 0,
  "attempt": 1,
  "createdAt": "2026-06-15T09:12:44.000Z",
  "startedAt": null,
  "finishedAt": null
}
```

`chunks` в этом ответе ещё ноль: число частей записывается в момент постановки
в очередь, уже после того как запись создана. В `GET /api/jobs/{jobId}` оно
будет настоящим.

## Ошибки

| Код | Когда |
|---|---|
| 400 | `Некорректный идентификатор` — `id` не UUID |
| 400 | `В документе нет ни одного блока — сначала соберите макет` — ни на одном листе материала нет блоков |
| 400 | `Не отмечено ни одной строки в таблице получателей` |
| 400 | `Генерация по этому документу уже идёт` — по материалу есть задание в статусе `queued` или `running` |
| 400 | `Одновременно можно выпускать не больше N пакетов. Дождитесь окончания или отмените лишний — документы уже созданные при отмене никуда не денутся.` — N это `ORG_ACTIVE_JOBS`, по умолчанию 3 |
| 400 | `Бесплатная проба закончилась: выпущено X документов из Y. Чтобы продолжить, выберите тариф на vruchay.ru. Или пригласите коллегу…` — на тарифе `free` не осталось ни одного документа |
| 400 | `На бесплатной пробе осталось N документов из Y, а отмечено M. Снимите лишние отметки или выберите тариф. Или пригласите коллегу…` — отмечено больше, чем осталось |
| 400 | Неизвестное значение `format` или отсутствующее тело — сообщение Zod |
| 401 | Нет токена или сессии |
| 404 | `Документ не найден` — нет такого, чужой или в корзине |
| 503 | `Очередь заданий сейчас недоступна, выпуск не начат. Ничего не списано — попробуйте ещё раз через минуту.` — Redis не принял пакет; задание при этом сразу закрывается со статусом `failed`, и позже его можно продолжить |

К обеим фразам про бесплатную пробу сервер добавляет ` (из них N держит
незаконченный выпуск)`, если часть остатка занята уже принятыми заданиями:
строки, которые воркер ещё не напечатал, считаются занятыми.

## Пример

```bash
curl -X POST "https://vruchay.ru/api/documents/$DOCUMENT_ID/generate" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"format":"pdf"}'
```
