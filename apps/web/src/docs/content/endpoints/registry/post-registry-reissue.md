# POST /api/registry/reissue

Выдать новый документ вместо выбранного — по текущим данным той же строки
таблицы получателей и текущему макету материала. Это не отзыв: старый
документ помечается заменённым, а его страница проверки указывает, где
взять новый. Перед перевыпуском исправьте строку получателя в материале —
новый файл печатается по ней.

Асинхронно. Ответ лишь подтверждает, что задания на выпуск поставлены в ту
же очередь, что и обычный выпуск, — по одному заданию на каждый материал
из выбранных документов. Пока задание идёт, у старого документа
`reissuePending: true`, состояние остаётся `valid`; когда новый файл
выпущен, старый получает `state: "replaced"` и `replacedBy`. Если выпуск
упал или его отменили, обещание замены снимается, и перевыпуск можно
заказать снова.

Перевыпуск создаёт новые файлы и на бесплатной пробе списывается с той же
квоты, что обычный выпуск (базовый лимит плюс бонус за приглашённых).
Формат нового файла (PDF или JPEG) берётся у первого документа пачки по
каждому материалу. В журнал пишется запись `registry.reissue`, если хоть
что-то перевыпущено.

## Запрос

Тело — JSON.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `fileIds` | UUID[] 1…500 | да | Документы, которые нужно заменить. |

```json
{ "fileIds": ["7d4c6e0a-1b2f-4c3d-9e8f-0a1b2c3d4e5f"] }
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| `reissued` | number | Сколько документов принято на перевыпуск. |
| `jobs` | array | Задания на выпуск, по одному на материал. |
| `jobs[].jobId` | string (UUID) | Идентификатор задания выпуска. |
| `jobs[].documentId` | string (UUID) | Материал. |
| `jobs[].total` | number | Сколько строк печатается в задании. |
| `skipped` | array | Документы, которые не перевыпускаются, с причиной. |
| `skipped[].fileId` | string (UUID) | Файл. |
| `skipped[].name` | string | Имя получателя. |
| `skipped[].reason` | string | Причина, см. ниже. |

Причины в `skipped[].reason`:

- «материал удалён — перевыпускать не из чего»;
- «материал в корзине — сначала восстановите его»;
- «строки больше нет в таблице получателей»;
- «документ уже заменён — перевыпускайте тот, что его заменил»;
- «перевыпуск уже заказан и ещё идёт»;
- «По этому материалу уже идёт выпуск — дождитесь его окончания» (вся пачка по материалу);
- «На бесплатной пробе осталось N документов из L, а на перевыпуск отмечено K. Перевыпуск создаёт новые документы и считается наравне с обычным выпуском.» (вся пачка по материалу).

```json
{
  "reissued": 2,
  "jobs": [
    { "jobId": "9a8b7c6d-5e4f-4a3b-2c1d-0e9f8a7b6c5d", "documentId": "b1c2d3e4-f5a6-4b7c-8d9e-0f1a2b3c4d5e", "total": 2 }
  ],
  "skipped": [
    {
      "fileId": "1f2e3d4c-5b6a-4978-8a9b-0c1d2e3f4a5b",
      "name": "Сидоров Пётр Ильич",
      "reason": "документ уже заменён — перевыпускайте тот, что его заменил"
    }
  ]
}
```

`reissued: 0` при непустом `skipped` — тоже `201`: отказ по каждому документу
объяснён в `skipped`, а не ошибкой.

## Ошибки

| Код | Когда |
|---|---|
| 400 | Пустой `fileIds` — «Не отмечено ни одного документа»; больше 500 — «За раз можно перевыпустить не больше 500 документов»; элемент не UUID — «Некорректный идентификатор документа». |
| 400 | Ни один из `fileIds` не найден в организации (чужие, удалённые) — «Ни один из документов не найден». |
| 401 | Нет токена или сессии. |
| 403 | Роль `member` — «Недостаточно прав для этого действия». |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/registry/reissue" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"fileIds":["'"$FILE_ID"'"]}'
```
