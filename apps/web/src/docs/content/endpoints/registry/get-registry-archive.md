# GET /api/registry/archive

Скачать пачку выданных документов одним ZIP-архивом: либо отмеченные по
идентификаторам, либо всё, что нашлось по отбору. Архив собирается потоком
прямо в ответ, поэтому размер ограничен числом файлов — не больше 2000 за
раз. У каждого попавшего в архив документа увеличивается `downloadCount`.

Идентификаторы передаются строкой через запятую, а не телом запроса:
скачивание задумано как переход по ссылке, чтобы браузер сам показал диалог
сохранения.

## Запрос

Параметры строки запроса — `ids` плюс общий отбор реестра
([reference/registry-filter.md](../../reference/registry-filter.md)). Если
передано и то и другое, условия складываются: берутся только те из `ids`,
которые проходят отбор.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `ids` | string ≤ 18 500 знаков | нет | UUID файлов через запятую. Не похожие на UUID куски молча отбрасываются, дубли схлопываются, берутся первые 500. |
| `search` | string ≤ 200 | нет | Имя, почта или проверочный код целиком. |
| `documentId` | UUID | нет | Материал. |
| `event` | string ≤ 200 | нет | Мероприятие, точное совпадение. |
| `state` | `valid` \| `revoked` \| `replaced` \| `expired` | нет | Состояние документа. |
| `mail` | `none` \| `queued` \| `sent` \| `delivered` \| `opened` \| `bounced` \| `failed` | нет | Состояние письма. |
| `from` | дата | нет | Выпущен не раньше этого дня (по Москве). |
| `to` | дата | нет | Выпущен не позже этого дня включительно. |

Без параметров вовсе — «всё выданное организацией», если оно умещается
в 2000 файлов.

## Ответ

`200 OK`, файл. Тело передаётся потоком, `Content-Length` не выставляется.

| Заголовок | Значение |
|---|---|
| `Content-Type` | `application/zip` |
| `Content-Disposition` | `attachment; filename="..."; filename*=UTF-8''...` (имя «Реестр — документы.zip») |

Внутри архива файлы лежат плоско, под своими исходными именами (или
`Документ.pdf` / `Документ.jpg`, если имени нет); повторяющиеся имена
получают числовой суффикс. Порядок — по дате выпуска, старые первыми.

## Ошибки

| Код | Когда |
|---|---|
| 400 | По отбору ничего не нашлось — «По этому отбору нечего скачивать». |
| 400 | Нашлось больше 2000 — «Документов слишком много для одного архива: больше 2000. Сузьте отбор — например, по мероприятию или по периоду.» |
| 400 | Ошибки отбора: «Некорректный идентификатор материала», «Неизвестное состояние документа», «Неизвестное состояние письма», «Не удалось разобрать дату начала периода», «Не удалось разобрать дату конца периода»; `ids` длиннее 18 500 знаков — стандартное сообщение Zod. |
| 401 | Нет токена или сессии. |

Чужие идентификаторы в `ids` не ошибка: они просто не находятся, и если не
нашлось ничего — ответ «По этому отбору нечего скачивать».

## Пример

```bash
curl "https://vruchay.ru/api/registry/archive?documentId=$DOCUMENT_ID&state=valid" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -o documents.zip
```

По отмеченным:

```bash
curl "https://vruchay.ru/api/registry/archive?ids=$FILE_ID_1,$FILE_ID_2" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -o documents.zip
```
