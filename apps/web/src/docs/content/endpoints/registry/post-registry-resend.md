# POST /api/registry/resend

Ещё раз отправить письмо с уже выпущенным документом — на адрес из текущей
строки получателя. Ничего не выпускает и квоту не трогает: к письму
прикладывается тот же файл. Тема и отправитель — из почтового шаблона
материала; если шаблона нет, письмо уходит со служебной темой от
отправителя организации по умолчанию.

Асинхронно: письма ставятся в очередь, ответ говорит лишь, сколько
поставлено. Состояние доставки смотрите потом в `mail` строки реестра или в
`emails` карточки документа. Предел — 50 писем за вызов: переотправка идёт
мимо проверки объёма рассылки на общем домене и задумана как «доотправить
тем, у кого не дошло», а не как массовая рассылка. В журнал пишется
запись `registry.resend`, если хоть одно письмо поставлено.

## Запрос

Тело — JSON.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `fileIds` | UUID[] 1…50 | да | Документы, письма с которыми нужно отправить заново. |

```json
{ "fileIds": ["7d4c6e0a-1b2f-4c3d-9e8f-0a1b2c3d4e5f"] }
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| `queued` | number | Сколько писем поставлено в очередь. |
| `skipped` | array | Документы, по которым письмо не поставлено, с причиной. |
| `skipped[].fileId` | string (UUID) | Файл. |
| `skipped[].name` | string | Имя получателя. |
| `skipped[].reason` | string | Причина, см. ниже. |

Причины в `skipped[].reason`:

- «материал удалён или в корзине — письмо слать не от чего»;
- «у получателя не указан адрес почты»;
- «Некорректный адрес»;
- «Отправка писем не настроена — обратитесь в поддержку»;
- «Домен отправителя не подтверждён — отправка невозможна».

```json
{
  "queued": 1,
  "skipped": [
    {
      "fileId": "1f2e3d4c-5b6a-4978-8a9b-0c1d2e3f4a5b",
      "name": "Сидоров Пётр Ильич",
      "reason": "у получателя не указан адрес почты"
    }
  ]
}
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | Пустой `fileIds` — «Не отмечено ни одного документа»; больше 50 — «За раз переотправляем не больше 50 писем»; элемент не UUID — «Некорректный идентификатор документа». |
| 400 | Ни один из `fileIds` не найден в организации — «Ни один из документов не найден». |
| 401 | Нет токена или сессии. |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/registry/resend" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"fileIds":["'"$FILE_ID"'"]}'
```
