# POST /api/documents/{id}/awards/preview

Прогоняет правила по таблице получателей документа и возвращает раскладку: кому какой шаблон полагается, сколько документов выйдет после дедупликации и какие строки остались без документа и почему. Ничего не сохраняет и ничего не выпускает.

Правила берутся из тела (`ruleSet`) или, если тела с набором нет, из набора, привязанного к документу через `POST …/awards/rule-set`. Метод POST именно ради первого случая: человек правит правила в конструкторе и хочет видеть результат, не сохраняя черновик в базу. Несохранённый набор проверяется теми же схемами, что и при сохранении, включая принадлежность шаблонов организации.

Рассматриваются только строки, отмеченные к выпуску (`checked: true`), по порядку в таблице, и не больше 5000 за раз. Если отмеченных больше, обрезка не замалчивается: в `problems` появляется строка «Отмечено строк: N, в раскладку взяты первые 5000…» — иначе тысяча человек осталась бы без документов до самого награждения.

Кем подписан участник в отчёте: берётся колонка `name`, а если её нет — первая колонка таблицы по порядку.

Расчёт идёт на сервере, хотя тот же движок есть и в браузере: перед выпуском решение принимает сервер, и показывать одно, а выпускать другое нельзя.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `id` | UUID (путь) | да | Идентификатор документа-соревнования |

Тело:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `ruleSet` | object | нет | Несохранённый набор правил в том же виде, что и тело `POST /api/award-rules` (`name`, `groupColumn`, `statusColumn`, `isDefault`, `rules`). Без него берётся набор, привязанный к документу |

Пустое тело `{}` — законный запрос: считать по привязанному набору.

```json
{
  "ruleSet": {
    "name": "Черновик",
    "groupColumn": "category",
    "statusColumn": "status",
    "rules": [
      {
        "id": "1c7b2e3f-2222-4b6c-9d0e-1f2a3b4c5d6e",
        "label": "Победители",
        "conditions": [{ "field": "place", "op": "placeEquals", "value": 1, "withinGroup": true }],
        "action": "issue",
        "outputs": [{ "templateDocumentId": "3a9e0c4d-3333-4c7d-8e1f-2a3b4c5d6e7f" }]
      }
    ]
  }
}
```

## Ответ

`201 Created`

| Поле | Тип | Описание |
|---|---|---|
| `plan` | AwardPlan | раскладка: `schemaVersion`, `items[]`, `summary[]`, `issues[]`, `totals` |
| `problems` | string[] | что не так с самим набором, а не со строками: правило «иначе» не в конце, правило без шаблона, дедупликация по группе без колонки группы, статус или место «внутри группы» без соответствующей колонки, а также предупреждение об обрезке протокола. Пустой массив — замечаний нет |

Поля `plan` (включая `items[]`, `summary[]`, `issues[]` с кодами `no-rule`, `excluded-by-rule`, `missing-group`, `unparsable-place`, `unknown-status`, `no-template`, `empty-subject`, `duplicate-subject` и все счётчики `totals`) разобраны в [reference/award-rules.md](../../reference/award-rules.md).

```json
{
  "plan": {
    "schemaVersion": 1,
    "items": [
      {
        "rowId": "6e5d4c3b-8888-4f01-9a23-6e7f80912345",
        "rowNumber": 1,
        "group": "Юноши 12-13",
        "subject": "Иванова Мария Сергеевна",
        "templateDocumentId": "3a9e0c4d-3333-4c7d-8e1f-2a3b4c5d6e7f",
        "templateTitle": "Диплом победителя",
        "ruleId": "1c7b2e3f-2222-4b6c-9d0e-1f2a3b4c5d6e",
        "ruleLabel": "Победители",
        "outputLabel": "",
        "mergedRowIds": []
      }
    ],
    "summary": [
      {
        "templateDocumentId": "3a9e0c4d-3333-4c7d-8e1f-2a3b4c5d6e7f",
        "templateTitle": "Диплом победителя",
        "ruleLabels": ["Победители"],
        "count": 1
      }
    ],
    "issues": [
      {
        "code": "no-rule",
        "severity": "error",
        "rowId": "7f6e5d4c-9999-4012-8b34-7f8091234567",
        "rowNumber": 2,
        "group": "Юноши 12-13",
        "subject": "Петров Олег Иванович",
        "message": "Не подошло ни одно правило — документ не выйдет. Добавьте правило или поставьте в конец списка правило без условий"
      }

      "rows": 2,
      "issuingRows": 1,

      "unmatchedRows": 1,
      "blockedRows": 0,

```

Тексты `message` у замечаний и порядок правил в сводке приходят готовыми к показу — их не нужно собирать на клиенте.

## Ошибки

| Код | Когда |
|---|---|
| 400 | `Некорректный идентификатор` — `id` не UUID |
| 400 | `К этому соревнованию не привязан набор правил — выберите его в разделе «Правила»` — тела с `ruleSet` нет и привязки у документа нет |
| 400 | `Выбранный шаблон недоступен: он удалён или лежит в корзине` — в черновике ссылка на чужой или удалённый шаблон |
| 400 | Сообщения схемы набора правил — как у `POST /api/award-rules` (`Введите название набора`, `Некорректное имя колонки`, `Выберите шаблон` и прочие) |
| 401 | Нет токена или сессии |
| 404 | `Документ не найден` |
| 404 | `Набор правил не найден` — привязанный к документу набор удалён |
| 413 | Тело больше 1 МБ |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/documents/$DOCUMENT_ID/awards/preview" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
```
