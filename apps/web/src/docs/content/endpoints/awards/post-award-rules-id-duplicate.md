# POST /api/award-rules/{id}/duplicate

Делает копию набора — «взять как на прошлом мероприятии и поправить». Тела у запроса нет.

Что происходит с копией: название — исходное с припиской ` — копия`, обрезанное до 200 символов; колонки группы и статуса, версия формата, а также все правила с их условиями, выходами и порядком переносятся как есть; признак «по умолчанию» у копии всегда `false`. Идентификаторы правил выдаются новые: у копии своя жизнь, и снимки прошлых раскладок должны ссылаться на исходные правила, а не на копии.

Повторный вызов сделает ещё одну копию — никакой проверки на существующую копию нет, названия могут совпасть.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `id` | UUID (путь) | да | Идентификатор копируемого набора |

Тела нет.

## Ответ

`201 Created` — новый набор в контракте `AwardRuleSet` (см. [reference/award-rules.md](../../reference/award-rules.md)); `id` набора и `id` каждого правила — новые.

```json
{
  "id": "9f2a4c6e-7777-4a1b-8c2d-3e4f5a6b7c8d",
  "name": "Награждение по протоколу — копия",
  "schemaVersion": 1,
  "groupColumn": "category",
  "statusColumn": "status",
  "rules": []
}
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | `Некорректный идентификатор` — `id` не UUID |
| 401 | Нет токена или сессии |
| 404 | `Набор правил не найден` — нет такого, он удалён или принадлежит другой организации |

## Пример

```bash
curl -X POST "https://vruchay.ru/api/award-rules/$RULE_SET_ID/duplicate" \
  -H "Authorization: Bearer $VRUCHAY_TOKEN"
```
