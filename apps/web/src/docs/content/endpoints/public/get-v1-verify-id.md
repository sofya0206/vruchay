# GET /api/v1/verify/{id}

Страница проверки выданного документа. Открыта без входа намеренно: её открывает
посторонний — работодатель, приёмная комиссия, судья на соревновании, — у которого
нет и не должно быть учётной записи. Заголовка `Authorization` здесь не нужно.

Отвечает скупо: только то, что и так напечатано на бумаге, которую человек держит
в руках. Почта, телефон, дата рождения и прочие колонки таблицы получателей не
показываются ни при каких настройках. Какие поля вообще попадут в ответ, решают две
вещи: список `verifyFields` материала (что отметила организация) и режим
`verifyNameMode` организации (как показывать имя) — см. ниже.

Каждый успешный ответ увеличивает обезличенный счётчик проверок документа
(`verifyCount` в реестре). Ни адрес, ни устройство проверяющего не сохраняются.

Действующий документ отдаётся с `cache-control: public, max-age=60,
stale-while-revalidate=60`; отозванный, заменённый и истёкший — с `no-store`,
чтобы отзыв доезжал до страницы сразу.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `id` | string 1…64 | да | Публичный код документа (`K7M2-9QXR-4TVB`) или `publicId` (UUID) у документов, выпущенных до появления кода. |

Код принимается как угодно набранным: строчными буквами, с пробелами и дефисами
в любых местах, с `O` вместо нуля и `I`/`L` вместо единицы. Готовый путь страницы
для каждого документа отдаёт реестр в поле `verifyPath`.

## Ответ

`200 OK`

| Поле | Тип | Описание |
|---|---|---|
| state | string | `valid` — действителен; `revoked` — отозван организацией; `replaced` — выдан новый взамен; `expired` — срок вышел. |
| valid | boolean | `state === "valid"`. |
| revoked | boolean | `state === "revoked"`. |
| replaced | boolean | `state === "replaced"`. |
| expired | boolean | `state === "expired"`. |
| code | string | Код, напечатанный на бумаге: публичный код или `publicId`. |
| title | string | Название материала. |
| event.name | string | Мероприятие (пустая строка — не указано). |
| event.date | string | Дата мероприятия как её ввела организация, строкой (пустая — не указана). |
| issuedAt | string (ISO 8601) | Когда документ выпущен. |
| expiresAt | string (ISO 8601) \| null | Когда истекает срок. `null` — бессрочный. |
| fields | object | Поля получателя: ключ — имя колонки, значение — строка. Пустой объект, если организация ничего не отметила, режим `none` или документ отозван. |
| issuer.name | string | Название выдавшей организации. |
| issuer.verified | boolean | Значок «Верифицированный эмитент». |
| issuer.publicPath | string \| null | Путь публичной страницы организации `/org/<slug>`. `null` — страница выключена или адрес не задан. |
| issuer.contactEmail | string \| null | Почта для связи («сообщить о проблеме»). `null` — не указана. |
| issuer.website | string \| null | Сайт организации. `null` — не указан. |
| indexable | boolean | Пускать ли поисковики на эту страницу. Решение организации. |
| sha256 | string \| null | Отпечаток выпущенного PDF для сверки. `null` у документов, выпущенных до того, как отпечаток стали сохранять. |
| signed | boolean | Подписан ли файл электронной подписью сервиса. |
| revokedAt | string (ISO 8601) \| null | Когда отозван. Заполнено только при `state: "revoked"`. |
| revokedReason | string \| null | Публичная причина отзыва. Только при `state: "revoked"`, и только если организация её указала. |
| replacedBy.code | string | Код документа-замены. |
| replacedBy.path | string | Путь страницы проверки замены: `/c/<код>` или `/verify/<uuid>`. |
| replacedBy.issuedAt | string (ISO 8601) | Когда выпущена замена. |

`replacedBy` — `null` во всех состояниях, кроме `replaced`, а также если саму замену
успели отозвать или удалить: вести человека на страницу, которая ответит «не найдено»,
хуже, чем отправить его в выдавшую организацию.

Что попадает в `fields`:

- организация отмечает в материале список показываемых колонок (`verifyFields`);
- поля с адресом почты, телефоном, датой рождения, паспортом, СНИЛС и ИНН
  выбрасываются всегда, даже если отмечены;
- дальше действует `verifyNameMode` организации: `full` — как отмечено;
  `initials` — колонки с именем (`name`, `fio`, `full_name`, `name_dat`,
  `name_gen` и т. п.) сворачиваются до фамилии и инициалов, остальные
  (клуб, место, город) остаются; `none` — `fields` пустой, наружу уходит
  только факт подлинности и название организации;
- у отозванного документа `fields` пустой в любом режиме: связывать причину
  отзыва с фамилией на открытой странице сервис не вправе.

Значения берутся из снимка данных на момент выпуска, а не из живой строки таблицы:
страница показывает то, что напечатано на бумаге, даже если строку потом поправили.

## Ошибки

| Код | Когда |
|---|---|
| 400 | `id` длиннее 64 знаков или пустой после обрезки пробелов — стандартное сообщение Zod. |
| 404 | Документ не найден, удалён, или проверка для его материала выключена. Тело нестандартное: `{"message":"Документ не найден","reason":"malformed"}` — без `statusCode` и `error`. |
| 429 | Больше 30 запросов в минуту с одного IP. |

Поле `reason` в ответе 404 объясняет, что не так с введённым кодом, и ничего
не говорит о чужих документах — все три значения выводятся из самого кода:

| `reason` | Что показать человеку |
|---|---|
| `malformed` | Это не похоже ни на код, ни на UUID: не те знаки или не та длина. |
| `checksum` | Похоже на код, но контрольный хвост не сходится — почти наверняка опечатка при переписывании с бумаги. Стоит перепроверить пары `0`/`O`, `1`/`I`, `1`/`L`, `5`/`S`, `8`/`B`, `2`/`Z`. |
| `unknown` | Форма верна, но такого документа нет или он закрыт для проверки. |

Отключённая проверка и несуществующий код отвечают одинаково: разные ответы
позволяли бы отличать «такого не было» от «был, но закрыт».

## Пример

```bash
curl "https://vruchay.ru/api/v1/verify/K7M2-9QXR-4TVB"
```

Старый выпуск — по тому же адресу с UUID:

```bash
curl "https://vruchay.ru/api/v1/verify/3f9a2b1c-5d6e-4f70-8a9b-0c1d2e3f4a5b"
```
