# GET /api/v1/public/org/{slug}/search

Поиск в публичном реестре эмитента — без входа. Два разных поиска в одном адресе,
и указывать надо ровно один из параметров:

- `code` — по номеру документа. Работает всегда, отвечает одним лишь путём
  страницы проверки: всё о документе говорит она, а здесь важно только,
  выдан ли такой номер этой организацией;
- `name` — по ФИО. Работает, только если эмитент сам включил такой поиск
  (`publicSearchByName`). Поиск по фамилии без согласия человека — это
  распространение персональных данных (ст. 10.1 152-ФЗ), и согласие собирает
  эмитент, а не сервис.

Предел строже, чем у страницы организации, втрое: поиск по ФИО — это перебор
чужих фамилий, и бесплатным он быть не должен.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `slug` | string, `^[a-z0-9-]{1,50}$` | да | Публичный адрес организации (параметр пути). |
| `code` | string 1…64 | ровно один из двух | Номер документа: публичный код или `publicId` (UUID). Регистр, пробелы и дефисы не важны. |
| `name` | string 1…200 | ровно один из двух | ФИО или его часть. Короче трёх знаков — ответ пустой. |

Указать оба параметра сразу или не указать ни одного — 400.

## Ответ

`200 OK`. Форма ответа зависит от того, чем искали.

Поиск по `code`:

| Поле | Тип | Описание |
|---|---|---|
| path | string | Путь страницы проверки: `/c/<код>` или `/verify/<uuid>`. |

```json
{ "path": "/c/K7M2-9QXR-4TVB" }
```

Поиск по `name`:

| Поле | Тип | Описание |
|---|---|---|
| items | array | Совпадения, не больше 20, новые первыми. |

Элемент `items`:

| Поле | Тип | Описание |
|---|---|---|
| code | string | Номер документа: публичный код или `publicId`. |
| path | string | Путь страницы проверки. |
| name | string | Имя получателя так, как разрешил показывать эмитент (`verifyNameMode`). При режиме `none` — пустая строка. |
| title | string | Название материала. |
| eventName | string | Мероприятие. |
| eventDate | string | Дата мероприятия строкой. |
| issuedAt | string (ISO 8601) | Когда выпущен. |
| state | string | `valid`, `revoked`, `replaced` или `expired`. |

```json
{
  "items": [
    {
      "code": "K7M2-9QXR-4TVB",
      "path": "/c/K7M2-9QXR-4TVB",
      "name": "Иванова М. П.",
      "title": "Сертификат участника",
      "eventName": "Открытый кубок города",
      "eventDate": "14.06.2026",
      "issuedAt": "2026-06-15T09:12:44.000Z",
      "state": "valid"
    }
  ]
}
```

Ищется только колонка `name`, по снимку данных на момент выпуска (у документов,
выпущенных до появления снимка — по живой строке таблицы). Совпадение —
вхождение подстроки без учёта регистра. Постраничности нет: сверх двадцати
совпадений ничего не отдаётся, запрос надо уточнять.

Запрос `name` короче трёх знаков после обрезки пробелов отвечает `{"items": []}`
без похода в базу: «Ив» вернуло бы половину реестра.

## Ошибки

| Код | Когда |
|---|---|
| 400 | `slug` не подходит под `^[a-z0-9-]{1,50}$` — «Некорректный адрес». Указаны оба параметра или ни одного — «Укажите номер документа или имя». `code` длиннее 64 знаков или `name` длиннее 200 — стандартное сообщение Zod. |
| 404 | Организации нет или её публичная страница выключена — «Организация не найдена». Поиск по ФИО не включён эмитентом — «Поиск по имени недоступен». Документа с таким номером у этой организации нет, он удалён или проверка для его материала выключена — «Документ не найден». |
| 429 | Больше 20 запросов в минуту с одного IP. |

Чужой и несуществующий номер отвечают одинаково: по ответу нельзя узнать,
существует ли такой документ у кого-то другого.

## Пример

```bash
curl "https://vruchay.ru/api/v1/public/org/fgso/search?code=K7M2-9QXR-4TVB"
```

```bash
curl --get "https://vruchay.ru/api/v1/public/org/fgso/search" \
  --data-urlencode "name=Иванова Мария"
```
