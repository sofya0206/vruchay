# GET /api/v1/reviews

Отзывы заказчиков для посадочной страницы сервиса. Без входа, заголовок
`Authorization` не нужен.

Отдаются только отзывы, прошедшие проверку человеком и опубликованные. Наружу
уходит ровно то, что автор согласился показать: имя, должность, организация,
текст и оценка. Ни адресов почты, ни идентификаторов организаций и отзывов
в ответе нет — по нему нельзя связать отзыв с учётной записью.

Свой отзыв организация оставляет через `PATCH /api/reviews/mine`.

## Запрос

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `limit` | integer 1…50 | нет | Сколько отзывов вернуть. По умолчанию 12. |

Постраничности нет: отдаётся первая страница, отсортированная по дате публикации,
новые первыми.

## Ответ

`200 OK`

| Поле | Тип | Описание |
|---|---|---|
| items | array | Отзывы, новые первыми. |

Элемент `items`:

| Поле | Тип | Описание |
|---|---|---|
| authorName | string | Как подписан автор. Заполняет он сам, из профиля не берётся. |
| authorRole | string | Должность автора. |
| orgName | string | Организация, от лица которой написан отзыв. |
| text | string | Текст отзыва, 40…2000 знаков. |
| rating | number \| null | Оценка 1…5. `null` — автор не поставил. |
| publishedAt | string (ISO 8601) | Когда отзыв опубликован. |

```json
{
  "items": [
    {
      "authorName": "Мария Петрова",
      "authorRole": "Ответственный секретарь",
      "orgName": "Учебный центр «Развитие»",
      "text": "Раньше на двести грамот уходило два дня: сверить фамилии, разложить по шаблону, разослать. Теперь загружаем таблицу и через полчаса рассылка уже ушла, а мы смотрим реестр — кто открыл письмо, кто нет.",
      "rating": 5,
      "publishedAt": "2026-05-20T10:03:00.000Z"
    }
  ]
}
```

## Ошибки

| Код | Когда |
|---|---|
| 400 | `limit` не целое число, меньше 1 или больше 50 — стандартное сообщение Zod. |

## Пример

```bash
curl "https://vruchay.ru/api/v1/reviews?limit=6"
```
