# Ограничения частоты

## Как это устроено

Лимит стоит не на всём API, а точечно — на маршрутах, где он действительно нужен: вход,
публичные формы, страница проверки подлинности, тяжёлая проверка таблицы. По умолчанию
маршрут ничем не ограничен.

Счёт ведётся по паре «маршрут + IP-адрес». Лимит на вход не расходуется обращениями
к публичной форме и наоборот. Счётчики общие для всех процессов приложения, лежат в Redis
и живут ровно одно окно.

Идентификатор организации в ключ не входит: ограничение защищает от перебора и наплыва
с одного адреса, а не делит квоту между клиентами. Объём выпуска ограничивается тарифом,
а не частотой запросов — см. `GET /api/org/usage`.

## Где лимиты есть

Из адресов, доступных по токену, ограничен только разбор таблицы получателей:

| Маршрут | Лимит |
| --- | --- |
| `POST /api/documents/{id}/validation` | 40 запросов за 5 минут |
| `POST /api/documents/{id}/validation/fix` | 80 запросов за 5 минут |
| `POST /api/documents/{id}/validation/exclude` | 80 запросов за 5 минут |

Публичные адреса, доступные без токена:

| Маршрут | Лимит |
| --- | --- |
| `GET /api/v1/verify/{id}` | 30 запросов в минуту |
| `GET /api/v1/public/org/{slug}` | 60 запросов в минуту |
| `GET /api/v1/public/org/{slug}/search` | 20 запросов в минуту |
| `GET /api/referral-offer` | 20 запросов за 5 минут |

Остальные маршруты кабинета — документы, получатели, выпуск, реестр, рассылка — частотой
не ограничены. Это не приглашение молотить их в тысячу потоков: сервис общий, и разумный
темп в ваших же интересах.

## Ответ при превышении

```
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
```

```json
{
  "statusCode": 429,
  "message": "Слишком много попыток. Повторите через 43 с."
}
```

Число секунд в сообщении — время до конца текущего окна. Отдельного заголовка
`Retry-After` в ответе нет, значение придётся взять из текста.

## Как вести себя программе

1. Не гонитесь за скоростью там, где ответ не изменится: список получателей и состояние
   задания меняются медленно.
2. Задание выпуска опрашивайте не чаще раза в 2–3 секунды. Тысяча документов печатается
   минутами, а не миллисекундами.
3. Получив `429`, подождите указанное число секунд и повторите. Повтор сразу же
   продлевает ожидание, а не сокращает его.
4. При недоступности Redis сервис считает обращения в памяти процесса. Лимит при этом
   становится мягче, но не исчезает.
