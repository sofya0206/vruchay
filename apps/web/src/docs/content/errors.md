# Ошибки

## Формат

Ошибка — это всегда JSON. Минимальный вид:

```json
{
  "statusCode": 404,
  "message": "Документ не найден",
  "error": "Not Found"
}
```

`message` написан по-русски и предназначен человеку: его можно показать в интерфейсе
как есть. Внутренних подробностей — путей, SQL, стека — в ответе нет никогда; они
остаются в журнале сервера.

Ошибка проверки тела запроса дополнительно перечисляет поля:

```json
{
  "statusCode": 400,
  "message": "Назовите токен — потом не разберётесь",
  "errors": [
    { "field": "name", "message": "Назовите токен — потом не разберётесь" }
  ],
  "error": "Bad Request"
}
```

- `errors[].field` — путь к полю через точку, например `rows.3.values.name`.
- `errors[].message` — что именно не так.
- `message` — сводка: до трёх разных причин через точку с запятой, дальше
  «— и ещё N». Длинное перечисление никто не дочитывает.

## Коды

| Код | Что значит | Что делать |
| --- | --- | --- |
| `200` | Успех | — |
| `201` | Объект создан. Ответ на `POST`, если не указано иное | — |
| `400` | Тело или параметры не прошли проверку | Исправить поля из `errors` |
| `401` | Нет токена, либо он неизвестен или отозван | Проверить заголовок `Authorization` |
| `403` | Не хватает роли, либо действие только для человека | См. [Аутентификация](authentication.md) |
| `404` | Объекта нет — или он принадлежит другой организации | Проверить идентификатор |
| `409` | Состояние не позволяет: например, повторный запуск уже идущего задания | Прочитать текущее состояние и решить |
| `413` | Тело больше допустимого | Разбить на части; предел — 1 МБ, у импорта выше |
| `429` | Слишком часто | Подождать, см. [Ограничения частоты](rate-limits.md) |
| `500` | Ошибка на нашей стороне | Повторить позже; текст ответа обобщённый |

## Одно исключение из формата

Публичная проверка подлинности `GET /api/v1/verify/{id}` отвечает на ненайденный
документ телом другой формы — без `statusCode` и `error`, зато с полем `reason`:

```json
{ "message": "Такого документа нет", "reason": "checksum" }
```

`reason` принимает значения `malformed` (код не той длины или с посторонними
знаками), `checksum` (опечатка — контрольная часть кода не сошлась) и `unknown`
(код правильный, но такого документа нет). Различие нужно, чтобы сказать
проверяющему «проверьте, не ошиблись ли при наборе» вместо «документа не
существует».

## Почему `404`, а не `403`

Обращение к объекту чужой организации отвечает `404`. Ответ `403` подтвердил бы, что
объект с таким идентификатором существует, — а это уже сведения о чужих делах. Поэтому
«не ваш» и «не существует» для API неразличимы.

## Разбор ошибок в программе

Ориентируйтесь на `statusCode` и на `errors[].field`. Тексты сообщений живут в схемах
проверки и меняются вместе с ними: сопоставлять их построчно — способ однажды сломаться
на исправленной опечатке.

Ошибки с кодами `4xx` повторять бессмысленно, пока не изменился запрос. Повторять стоит
`429` (после паузы) и `500` (с нарастающей задержкой).
