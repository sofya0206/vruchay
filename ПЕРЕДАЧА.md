# Передача проекта разработчику

Сервис **«Вручай»** — массовая выдача именных наградных документов
(грамоты, дипломы, сертификаты) для спортивных федераций, школ
и организаторов соревнований. Работает в бою: **https://vruchay.ru**

---

## Первым делом: ключей в этом репозитории нет

`.env` с боевыми значениями сюда **не попадает и не должен попасть**.
В git история не стирается: удалив файл следующим коммитом, вы не удалите
его из истории — только добавите ещё один коммит. А это ключи от базы,
хранилища, почтовой рассылки и резервных копий системы, где лежат
персональные данные детей — участников соревнований.

Владелец передаст ключи отдельно (менеджер паролей или шифрованный файл).
Здесь лежит **`.env.prod.example`** — там все 42 переменные с пояснениями,
что каждая делает и что будет, если её не задать.

Если понадобится добавить переменную — добавляйте её в три места сразу:
`apps/server/src/config/env.ts` (схема проверки), `.env.prod.example`
(образец) и в боевой `.env` на сервере. Схема при запуске проверяет
всё разом и падает с внятным сообщением, если чего-то нет.

## За полчаса: поднять у себя

Нужны Node 22+, pnpm и Docker.

```bash
pnpm install
cp .env.example .env
docker compose -f docker-compose.dev.yml up -d    # база, Redis, почта, хранилище
pnpm -C apps/server prisma migrate deploy
pnpm -C apps/server dev                            # API на :3000
pnpm -C apps/web dev                               # интерфейс на :5173
```

Письма локально не уходят наружу — их ловит Mailpit на **:8025**.

Создать себе владельца:

```bash
OWNER_EMAIL=you@test OWNER_PASSWORD=DlinnyiParol2026 ORG_NAME='Проверка' \
  pnpm -C apps/server exec tsx src/cli.ts create-owner
```

## Из чего собрано

Монорепо на pnpm workspaces, весь код на TypeScript.

| Что | Чем |
|---|---|
| Сервер | NestJS 11 на Fastify, Prisma, PostgreSQL 16 |
| Очереди | BullMQ на Redis |
| Интерфейс | React 19, Vite 7, Tailwind v4, TanStack Query |
| Печать PDF | Playwright + Chromium в отдельном воркере |
| Хранилище | S3 (Selectel, аттестованный пул `gis-1`) |
| Эксплуатация | Docker Compose, Caddy для TLS |

```
apps/server   — API и воркер (один образ, роль решает RUN_WORKER)
apps/web      — кабинет, посадочная, страница печати
packages/shared — то, что общее у сервера и интерфейса
docs/         — решения, инструкции, бизнес-документы
```

### Три решения, которые стоит понять до правок

**1. Один компонент отрисовки на всё.** `SheetRenderer.tsx` рисует лист
и в редакторе, и в предпросмотре, и на странице печати, которую открывает
браузер воркера. Совпадение того, что видно на экране, и того, что уйдёт
в PDF, обеспечено конструкцией, а не аккуратностью. Не заводите второй
путь отрисовки.

**2. Изоляция по организации.** `orgId` берётся **только из сессии**,
никогда из тела запроса. Чужой объект отдаёт 404, а не 403: по 403 можно
узнать, что объект существует. Это единственное, что отделяет данные
одного клиента от другого.

**3. Считаем по фактам, а не по счётчикам.** Остаток бесплатной пробы,
бонусы за приглашения, однократность выдачи — всё выводится из записей,
а не хранится отдельным числом. Счётчик пришлось бы чинить при каждой
ошибке, отмене и удалении, а факты чинить не нужно.

## Выкладка

```bash
ssh -i ~/.ssh/vruchay root@СЕРВЕР 'cd /opt/vruchay/src && ./scripts/server-deploy.sh'
```

Скрипт делает четыре шага: место на диске → сборка образов → запуск
и миграции → проверка. Подробности и разбор поломок — в
[RUNBOOK.md](RUNBOOK.md), пошагово для новичка —
[docs/установка-по-шагам.md](docs/установка-по-шагам.md).

**Перед выкладкой прогоните боевую конфигурацию у себя:**

```bash
./scripts/prod-dry-run.sh
```

Это не формальность. 07.08.2026 выкладка положила бой на четверть часа
из-за настройки, которая ломается только в боевой конфигурации. Проверка
на своей машине поймала бы это за пять минут.

Проверка боя после выкладки:

```bash
BASE=https://vruchay.ru ./scripts/smoke.sh
```

## Что работает

Выпуск и рассылка документов, редактор макета, импорт списков из Excel
и CSV, проверка подлинности по QR, реестр выданных, приём заявок с чужих
сайтов (Тильда, WordPress, Битрикс), сотрудники и роли, журнал действий,
счета, приглашения друзей, отзывы, API с токенами.

Тесты: **227 на сервере, 89 в интерфейсе.** Гоняются `pnpm -C apps/server
exec vitest run` и то же для `apps/web`.

## Что не доделано

Список ведётся в [docs/план.md](docs/план.md) и там же объяснено, почему
каждое отложено. Коротко:

- **живой прогон восстановления пароля** — логика есть и покрыта тестами,
  но круг «письмо → ссылка → новый пароль» на бою не проходили;
- **проверка на настоящей странице Тильды** — единственный кусок,
  ни разу не проверенный вне localhost;
- **приём платежей** — модуль ЮKassa написан, ключей нет;
- **почтовый ящик на домене** — записей MX нет, DMARC-отчёты идти некуда;
- **наблюдение UptimeRobot** — не включено.

## Требования закона, которые нельзя нарушить

Сервис обрабатывает персональные данные граждан РФ, включая
несовершеннолетних. Отсюда несколько жёстких рамок:

- **вся инфраструктура в России**, сервер в аттестованном сегменте
  Selectel — это требование ВФЛА, и оно проверялось;
- **резервные копии шифруются** (`age`), приватного ключа на сервере нет:
  доступ к серверу не даёт доступа к прежним копиям;
- **адреса в журналах маскируются**;
- **любой новый подрядчик, который увидит данные участников, требует
  договора-поручения** по ч. 3 ст. 6 152-ФЗ — до подключения, а не после.

Подробности — [docs/business/перечень-пдн.md](docs/business/перечень-пдн.md)
и [docs/threat-model.md](docs/threat-model.md).
